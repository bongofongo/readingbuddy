# crates/cli (bin `readingbuddy`)

Moved here from the root `CLAUDE.md` unchanged.

**All printing and prompting lives here** (`prompt.rs`, `render.rs`) — the
engine does no terminal I/O. That rule is about *terminal I/O*, not about
derived facts: sorting rules, progress arithmetic and row-state joins belong in
the engine even though their *phrasing* belongs here. See
`docs/gui/spec-gui-17-28.md` item 17.

Run it: `cargo run -p readingbuddy-cli -- <subcommand>` (`--help` for the tree;
`repl` for interactive mode).

Siblings: [`../engine/CLAUDE.md`](../engine/CLAUDE.md) ·
[`../tui/CLAUDE.md`](../tui/CLAUDE.md) (the other frontend — do not copy logic between them)

clap derive subcommands (`search`, `add`, `epub`, `list`, `show`, `toc`, `activity`, `rm`, `progress [--reread]`, `note`, `notes`, `links`, `reflect`, `review`, `cite`, `rating scale|map|show`, `highlights`, `merge`, `goodreads import|export`, `calibre status|convert|import`, `ko import|pull|link|scan|watch|sync|stats`, `cards`, `covers`, `config`, `repl`). `list --sort` takes all five of the engine's keys (`last-modified | title | progress | author | year`) — item 17 added `author` and `year` and this `match` was the only door, so for a wave they existed and nothing could ask for them; a sort with no caller is a sort nothing exercises. `progress` and `show` name the *readings* they touch, not just the book — with rereads one book carries several; `reflect`/`review` take `--reading N` in those same 1-based terms and print the reading they opened. `highlights` **groups by read in those same terms** once a book has more than one, printing each reading's header even when it marked nothing (a read that found nothing is a different fact from a read the list forgot), then the unattributed ones last under `not placed in a reading` — listed plainly, since they are ordinary highlights rather than a queue of work. One reading prints flat: a header over the whole list says nothing. Both reuse `prompt::edit_in_editor`, and `--show`/`--no-edit` exist so opening one is never forced through an editor. `note --kind reflection|review` is refused with the command that does it instead — those two anchor to a reading and there is one of each, which `note` knows nothing about. `rating show` prints every point of the scale including the **unmapped** ones, because an unmapped point is what a review on that value will report instead of a number. `links <note>` prints both directions of the graph and marks a **dangling target as text** rather than dropping it — a wikilink to a note nobody has written is a place to go, not an error; it takes an id or a title fragment through `commands::resolve_note`, the note-side twin of `resolve_one`, because a title is what a `[[wikilink]]` names. `goodreads import <file> [--dry-run] [--new]` and `goodreads export [-o file]`: `--dry-run` prints what would change and names the command that does it, the same refusal-with-a-next-move shape as `ko sync`, and an unmatched row prints its candidates and both moves rather than being a dead end. `ko scan [path]` is read-only and finds the mount itself when the path is omitted (`candidate_mounts`), refusing to guess when two readers are plugged in; `ko sync <path>` with **neither `--all` nor `--book`** prints what would happen and names the flag rather than writing forty books unasked, and an unmatched `--book` selector is an error, never a silent no-op. `ko watch` blocks until a reader is plugged in and then scans it — the headless half of the mount watcher, and the instrument the wired path is confirmed with on real hardware; it prints the sync command rather than running it, like everything else on the automatic path. `ko pull` refuses to create a book when the library holds a near-miss candidate (`--new` overrides) — creating first and warning after would reproduce the silent duplicate `match_candidates` exists to prevent; `ko link` records the decision and then imports, so linking is not a step that appears to do nothing. `calibre status` exists because feature detection is otherwise invisible — it prints where each tool was found and what that enables, and with calibre absent it **reports and stops**: no failure, and nothing named to install, which is `docs/decisions.md`'s rule and the sort that erodes by helpfulness (`an_absent_calibre_is_reported_and_never_prescribed` asserts the wording, and asserts it as a pure function because on a machine with calibre the absent branch is unreachable from outside the process). `calibre convert IN OUT [--force]` refuses to overwrite by default and names the flag; `calibre import [--library P] [--dry-run] [--new]` takes the same refusal-with-a-next-move shape as `goodreads import`. **The surfacing item added `toc`, `activity`, `ko stats` and three `set` flags**, and every one of them is a rule about *absence*. `toc` has **three answers, not two** — no readable file, an epub with no TOC, and the list — because collapsing the first two makes an ordinary EPUB3 book look like a missing file with no move for either. `activity` prints `—` in an unmeasured column and the words **"not measured"** in place of a total, **never `0`**: a library that arrived as a Goodreads CSV has no minutes, and a zero there is a false statement about the user's own reading (`nothing_measured_is_never_printed_as_zero` pins it, and a sibling asserts that no word of streak/goal/"n of 30" framing appears). An empty log **names `activity --refill`** rather than being a dead end, since no importer fills `reading_events` and "nobody has built it" is not "you did not read". `ko stats` is its own verb for the engine's reason (arrival is read-only) and prints `books_in_db` against `books_matched` even when nothing imported, because a device full of unmatched books and a device with no statistics database need different next moves. `set --subject/--series/--series-index` **refuses an index with no series** — checked against the *stored* series too, so renumbering a book already in one is allowed — and warns when renaming a series leaves an old number behind, since `set_book_fields` sets and cannot clear. `covers` is the door onto item 20's back-fill, and it is here because it had no door at all for a wave: `Engine::measure_stored_covers` was tested on the facade and unreachable from outside the process, so every library built before migration `0014` — `make dev-db`'s included — carried a `cover_path` and a NULL `cover_aspect`, and a shelf reading that column would have concluded the column does not work. Same failure as `list --sort author`: the engine can do it and nothing can ask. It is a command and not a migration for the engine's reason (`cover_width` is the result of decoding a PNG, and SQLite cannot decode one), it is idempotent, and **its wording obeys both absence rules** — an already-measured library says so rather than reporting `measured 0 covers`, and an unreadable file states what happened to it (nothing was written; the next run retries it) rather than becoming a count of work you have not done. `make dev-db` runs it, so the second and every later line it prints is the already-measured one. `sort-keys` is item 34's twin of it and is there for the same reason one layer over — `sort_title` drops a leading article and `sort_author` is a parse of a human name, and SQLite can do neither — with one difference worth knowing: this back-fill has a **sharper edge**, because until it runs a book files at the *top* of `list --sort author` rather than under its author, so a function nothing calls is not merely unexercised but visibly wrong. Same wording rules (`every book already files under a sort key`, never `filed 0 books`), same `make dev-db` line, and the seed still writes `sort_title` as NULL on purpose so the door is exercised on every rebuild. All printing/prompting lives here (`prompt.rs`, `render.rs`).

- Google Books key: precedence `--google-api-key` flag > `GOOGLE_BOOKS_API_KEY` env (clap merges these) > `~/.config/readingbuddy/config.toml` (`config_file.rs`, written mode 600, XDG-aware). `config set google-api-key` uses a hidden rpassword prompt; `--verify` live-checks via `readingbuddy::verify_google_key`. `config` runs WITHOUT opening the engine (must not create `database/` as a side effect). Keys are redacted from all error/warning output via `googlebooks::scrub_key` — keep it that way for any new provider error path.
