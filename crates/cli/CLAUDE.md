# crates/cli (bin `readingbuddy`)

Moved here from the root `CLAUDE.md` unchanged.

**All printing and prompting lives here** (`prompt.rs`, `render.rs`) — the
engine does no terminal I/O. That rule is about *terminal I/O*, not about
derived facts: sorting rules, progress arithmetic and row-state joins belong in
the engine even though their *phrasing* belongs here. See
`docs/gui/spec-gui-17-28.md` item 17.

Run it: `cargo run -p readingbuddy-cli -- <subcommand>` (`--help` for the tree;
`repl` for interactive mode).

Siblings: [`../engine/CLAUDE.md`](../engine/CLAUDE.md) ·
[`../tui/CLAUDE.md`](../tui/CLAUDE.md) (the other frontend — do not copy logic between them)

clap derive subcommands (`search`, `add`, `epub`, `list`, `show`, `rm`, `progress [--reread]`, `note`, `notes`, `links`, `reflect`, `review`, `cite`, `rating scale|map|show`, `highlights`, `merge`, `goodreads import|export`, `calibre status|convert|import`, `ko import|pull|link|scan|watch|sync`, `cards`, `config`, `repl`). `progress` and `show` name the *readings* they touch, not just the book — with rereads one book carries several; `reflect`/`review` take `--reading N` in those same 1-based terms and print the reading they opened. `highlights` **groups by read in those same terms** once a book has more than one, printing each reading's header even when it marked nothing (a read that found nothing is a different fact from a read the list forgot), then the unattributed ones last under `not placed in a reading` — listed plainly, since they are ordinary highlights rather than a queue of work. One reading prints flat: a header over the whole list says nothing. Both reuse `prompt::edit_in_editor`, and `--show`/`--no-edit` exist so opening one is never forced through an editor. `note --kind reflection|review` is refused with the command that does it instead — those two anchor to a reading and there is one of each, which `note` knows nothing about. `rating show` prints every point of the scale including the **unmapped** ones, because an unmapped point is what a review on that value will report instead of a number. `links <note>` prints both directions of the graph and marks a **dangling target as text** rather than dropping it — a wikilink to a note nobody has written is a place to go, not an error; it takes an id or a title fragment through `commands::resolve_note`, the note-side twin of `resolve_one`, because a title is what a `[[wikilink]]` names. `goodreads import <file> [--dry-run] [--new]` and `goodreads export [-o file]`: `--dry-run` prints what would change and names the command that does it, the same refusal-with-a-next-move shape as `ko sync`, and an unmatched row prints its candidates and both moves rather than being a dead end. `ko scan [path]` is read-only and finds the mount itself when the path is omitted (`candidate_mounts`), refusing to guess when two readers are plugged in; `ko sync <path>` with **neither `--all` nor `--book`** prints what would happen and names the flag rather than writing forty books unasked, and an unmatched `--book` selector is an error, never a silent no-op. `ko watch` blocks until a reader is plugged in and then scans it — the headless half of the mount watcher, and the instrument the wired path is confirmed with on real hardware; it prints the sync command rather than running it, like everything else on the automatic path. `ko pull` refuses to create a book when the library holds a near-miss candidate (`--new` overrides) — creating first and warning after would reproduce the silent duplicate `match_candidates` exists to prevent; `ko link` records the decision and then imports, so linking is not a step that appears to do nothing. `calibre status` exists because feature detection is otherwise invisible — it prints where each tool was found and what that enables, and with calibre absent it **reports and stops**: no failure, and nothing named to install, which is `docs/decisions.md`'s rule and the sort that erodes by helpfulness (`an_absent_calibre_is_reported_and_never_prescribed` asserts the wording, and asserts it as a pure function because on a machine with calibre the absent branch is unreachable from outside the process). `calibre convert IN OUT [--force]` refuses to overwrite by default and names the flag; `calibre import [--library P] [--dry-run] [--new]` takes the same refusal-with-a-next-move shape as `goodreads import`. All printing/prompting lives here (`prompt.rs`, `render.rs`).

- Google Books key: precedence `--google-api-key` flag > `GOOGLE_BOOKS_API_KEY` env (clap merges these) > `~/.config/readingbuddy/config.toml` (`config_file.rs`, written mode 600, XDG-aware). `config set google-api-key` uses a hidden rpassword prompt; `--verify` live-checks via `readingbuddy::verify_google_key`. `config` runs WITHOUT opening the engine (must not create `database/` as a side effect). Keys are redacted from all error/warning output via `googlebooks::scrub_key` — keep it that way for any new provider error path.
