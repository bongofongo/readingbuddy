## The rule

**Zero terminal I/O**: no `println!`, no stdin. All user interaction belongs in frontends. Errors are a typed `thiserror` enum (`EngineError`); `anyhow` is CLI-only.

## Modules

- `lib.rs` — `Engine` facade (owns `Storage`, provider list, shared `reqwest::Client`, `EngineConfig`). Frontends call this.
  - **`storage` and `config` are private fields (item 14)**, and that is the seam. Every frontend used to reach through them; the facade now has a method for each of those call sites — `list_books`, `get_book`, `book_tags`, `list_readings`/`get_reading`/`active_reading`/`update_progress`/`reread`, `list_highlights`/`set_annotation`, `get_note`/`note_for_reading`/`note_path`, `book_file`, `fetch_cover`, the whole of rating-scale admin, `uncite` — plus six narrow path accessors (`db_url`, `images_dir`, `vault_dir`, `files_dir`, `log_dir`, `google_api_key`). **Six accessors rather than one `config()`** because of the key: `set_google_api_key` writes a live copy and `EngineConfig`'s field is only the seed, so a struct getter would hand out the stale one beside the live one with no way to tell at the call site. `Engine::storage()` survives behind the **`internals` feature**, which only the engine's own `tests/` and the TUI's dev-dependencies switch on — a separate crate cannot see `pub(crate)`, and inventing an `add_highlight` facade method to make a fixture compile would add product surface no product asked for. A plain `cargo check --workspace` is what stops that door being used in production code.
  - **`set_google_api_key` takes `&self`.** The transport hands one engine to several connections through an `Arc`, and `&mut self` on a facade is a method no shared owner can call. So the provider list is an `Arc` behind an `RwLock` — cloned out of the guard, never held across an await, because a federated search takes seconds and a key change must not wait for one — and both locks recover from poisoning rather than panicking, since neither value has an invariant a half-write could break.
- `book.rs` — `Book` domain struct + `normalize_isbn`/`isbn10_to_13`. **ISBNs are TEXT**, checksum-validated (i64 storage was a bug: leading zeros, X check digit). Identity: internal `id` canonical, ISBNs unique lookup keys.
- `koreader.rs` — parses `.sdr` sidecars by evaluating the Lua chunk in a sandboxed `mlua` VM (`StdLib::NONE`); handles modern `annotations` and legacy `highlight`+`bookmarks` formats. Imports are idempotent via sha256 identity hash (`identity_hash = sha256(book_id | ko_datetime | pos0 | text)`, `ON CONFLICT DO NOTHING`).
  - **Ownership seam (migration `0004`).** `highlights.note` is now `ko_note` (theirs) beside `annotation` (ours, never written by import) and `last_seen_ko_note` (unused today; a future two-way sync cannot tell "changed here" from "changed there" if only the merged result is ever stored). `insert_highlight` stays `DO NOTHING` — `DO UPDATE` would make `RETURNING id` yield a row on the conflict path, so `Some(id)` would stop meaning "newly inserted" and the inserted/skipped counts the goldens assert would collapse. Instead the `None` arm calls **`refresh_device_fields`**, which rewrites `ko_note`/`color`/`chapter`/`page` toward the device and returns whether anything actually changed; that boolean is `BookImportStats::updated`, and `skipped` now narrows to "present and identical". **Straight assignment, not `COALESCE`** — the books upsert's no-clobber merge is right for *providers* (partial records, missing means "don't know") and wrong here (a sidecar is the complete state, so a missing note means the user deleted it). The predicate lives once in `DEVICE_FIELDS_DIFFER` and is shared with `device_fields_differ`, so the dry-run preview cannot disagree with the import it previews. The refresh updates **in place**: `notes.highlight_id`/`flashcards.highlight_id` are foreign keys, so delete-and-reinsert would null note anchors and cascade flashcards away — guarded by `highlight_ids_are_stable_across_refresh`. Single-word highlights auto-become flashcard candidates (note: space-less CJK text counts as one "word" — see the Unicode fixture golden). Coverage lives in the data-driven harness `crates/engine/tests/koreader_import.rs` + the fixture corpus under `crates/engine/tests/fixtures/koreader/`: `synthetic/<Title>.sdr/metadata.epub.lua` cases (modern/legacy/multi-chapter/unicode/empty/malformed/unmatched) each paired with a golden JSON in `expected/` and seed books in `manifest.json`; `real/` is a **gitignored drop-in** for the user's own exports. The harness asserts golden match, strict idempotency (re-import inserts 0, no row mutates), append-only on superset re-import, and non-fatal malformed/unmatched handling. Regenerate goldens with `make golden` (`UPDATE_GOLDEN=1`).
  - **Pull from the device (item 3).** `import_book_from_sidecar` creates the book from the sidecar's own metadata (`stats` → `doc_props`/`doc_pages`; `N/A` filtered, authors newline-split) and then imports its highlights — **fully offline, no provider enrichment**, so no ISBN, cover or description. **Idempotency cannot come from `upsert_book`**: it branches isbn_10 → isbn_13 → plain unconditional insert, and a sidecar-seeded book has neither ISBN, so a second pull would create a second book. The guard is `device_books` keyed on `partial_md5`; a sidecar without one still imports but emits `DiagnosticKind::SidecarNotIdentified`, because the duplicate would otherwise appear silently much later. Matching order is **`device_books` md5 → sibling-epub ISBN → `matching.rs` score ≥ `AUTO_MATCH` → candidate band → New**: `match_candidates` returns `CANDIDATE_MIN..AUTO_MATCH` (0.60/0.85, `const` for the same reason `PROVIDER_TIMEOUT` is) and passes the sidecar's own `authors` beside its title, and `UnmatchedSidecar` now carries them plus the device key, so unmatched is a decision rather than a dead end. `link_sidecar` records the user's choice as `Manual` via `Storage::set_device_link`, which **repoints** — deliberately unlike `link_device_book`, which a library scan uses and which must never relabel a manual link.
  - **`Storage::merge_books`** folds a duplicate back in, and exists because the ISBN-less insert path guarantees duplicates however good matching gets. Lives in `storage/` (all SQL does), not `koreader.rs` — merging two books is not KOReader's business. **One transaction**: a half-merged library is worse than the duplicate. `book_id` is an input to a highlight's `identity_hash`, so every moved row's hash is recomputed via the shared `identity_hash_of`; a row that then collides is the *same annotation* and is **dropped, not duplicated**, after its notes and flashcards are repointed at the survivor (deleting first would cascade the flashcards away and null the note anchors). Flashcards are `UNIQUE(book_id, word)`, so shared words drop too. Field merge is `COALESCE`-style with **`dst` winning** — the inverse of `upsert_book`. `src` is deleted *before* `dst`'s fields are filled, because both ISBN columns are UNIQUE. Idempotent: a repeat merge finds `src` gone and returns `src_existed: false` with every count zero, which is what `merging_twice_equals_merging_once` asserts.
- `device.rs` — **reading a mounted reader** (item 6a). Deliberately *not* in `koreader.rs`: a scan is not an import. `import`'s `dry_run` previews a tree, but it evaluates every sidecar's Lua in mlua first — several hundred VM runs every time the screen opens — and answers "what would import" rather than "what state is each book in". `scan_device` is read-only and returns a `DeviceState` per book (**New{candidates} / Unchanged / Updated{new,refreshed} / Unreadable(Diagnostic)** — the four `docs/decisions.md` names, with the existing `SidecarUnreadable`/`SidecarUnparsable` vocabulary rather than a parallel taxonomy); `sync_device` writes, one `PullReport` per book so a frontend can show per-book progress. `is_koreader_mount`/`koreader_dir` know all three install layouts (`koreader/` Kindle, `.adds/koreader` Kobo, `applications/koreader` PocketBook) and require `reader.lua` + `frontend/` + `plugins/` inside — **not cosmetic**: this is the gate that will refuse to install the plugin onto an unrecognised volume.
  - **The pre-filter cache — `sidecar_seen`, migration `0006`.** `stat` first; when `(size, mtime)` match the cached row the parse is skipped. **It caches the parse, never the verdict** — a book deleted here, or linked since, changes a sidecar's state without touching the file, so New/Unchanged/Updated is recomputed from the DB every scan. Every column is something the *file* said, which is why `title`/`authors`/`ko_percent`/`ko_status` live there too: without them a cache hit could not be matched or displayed and would have to re-parse, i.e. do nothing. `title` is `doc_props.title` **exactly**, because it is fed back to `koreader::match_book` (made `pub` for this) and a cache hit must reach the verdict a fresh parse would. `mtime` is **nanoseconds**: a device flushes on every page turn and two edits in one second are ordinary.
  - **The cheap path compares a digest, not a row count.** A count was the first cut and is wrong: a note rewritten on the device leaves it identical, so the edit was reported by the one scan that re-read the file and by no scan after it — the cache then said "unchanged" forever about a change it had already seen. `sidecar_seen.entry_digest` and `Storage::device_highlight_digest` both go through **`DeviceDigest`** (identity + the four device-owned fields, `annotation` deliberately absent, sorted in `finish` so neither side owes an ordering) — one formula, same rule as `identity_hash_of` and `DEVICE_FIELDS_DIFFER`.
  - The prune of vanished sidecars compares `last_seen <> token`, **not `< started`**: at second resolution a scan finishing in the same second as the last one prunes nothing and never fails. One nanosecond token per scan, stamped on every row it touches. Scoped by path prefix via `substr`, not `LIKE` (a `%` in a volume name is a wildcard) and with the separator appended (`/mnt/a` is not a prefix of `/mnt/abc`).
  - A sidecar that does not parse is **not cached** — every column is what the file said, and it said nothing — so it is re-read each scan. That is the right price for the one or two a real device has, and it is why "a second scan parses zero" is asserted over a tree of valid sidecars.
- **`watch.rs` — noticing a reader without being asked (item 11).** The engine surface for a mount already existed; what was missing was *noticing*. A `MountWatcher` debounces raw `MountStir`s off a **channel**, and `watch_mounts()` is a thin `notify` adapter that fills it — **the seam is the whole reason this is testable**: a watcher that can only be driven by plugging in real hardware is a watcher with no tests, and the debounce is exactly the part that has to be tested. **It may scan; it may not sync**: the module holds no `Storage` at all, so `docs/decisions.md`'s "read-only on arrival" is a property of the code rather than a rule about it. Four things are decisions. **The debounce is the substance** (`MOUNT_QUIET` = 2s, a `const` for the same reason `PROVIDER_TIMEOUT` is): a mount is a *burst*, and a reader still flushing hands over a sidecar mid-write, so scanning on the first event reads a half-written file and calls it `Unreadable`. **`present` is what stops one mount starting two scans** — a volume that is still plugged in is not news however loudly the platform says so, and only a departure makes it newsworthy again. **The watcher reports transitions**, so a reader already mounted at startup is *seeded* (`already_here`), not announced — `candidate_mounts` is what answers that question, and announcing it here would scan a device the caller was already told about. **`next()` is cancel-safe by construction**: every deadline and every decided-but-unhandled event lives in the struct, not in the future, because the TUI's `select!` drops it on every keypress. The `notify` watch is **non-recursive** — `/Volumes` recursively is every file on every mounted disk — and an event path is reduced to the volume it happened on (`normalize`), or a page turn rewriting a sidecar would rescan the device on every page turn. A stir at a *root* cannot name a volume, so it is expanded when it settles, against `read_dir` **and** against `present`: a departure derived only from what is on disk is a departure that never fires. `device.rs` grew `mount_roots`/`offers_reader` so the watcher and the lister cannot disagree about what counts as a reader. `notify` is CC0-1.0 — a deliberate `deny.toml` entry.
- `notes.rs` — vault of markdown files (`vault/<book-slug>/<timestamp>-<slug>.md`, hand-rolled frontmatter, Obsidian-openable). A note anchors to a book plus optional `page`/`location`/`highlight_id` (migration `0002`); `frontmatter_and_body` splits the raw header from the body so `Engine::update_note_body` can rewrite the body while preserving frontmatter. DB keeps metadata + `note_links` (wikilink edges, dangling targets kept as text and back-resolved) + FTS5 index (ordinary fts5 table as searchable body cache; delete+insert on save). `delete_note` removes the vault file + row + edges; the FTS row must be `DELETE`d explicitly (a virtual table can't be reached by a foreign-key cascade), while `note_links` do cascade (from_note CASCADE, to_note SET NULL → links pointing at a deleted note degrade to dangling text).
  - **Walking the graph (migration `0008`).** `Storage::backlinks` ("what links here") and `Storage::outgoing_links` (the same edges plus the target row) are the two directions, surfaced on the facade as `Engine::backlinks`/`Engine::outgoing_links` and by `rb links <note>`; before this the facade exposed no link method at all. **`backlinks` is a plain `WHERE to_note = ?`, deliberately without a dangling-by-title union.** `write_links` back-resolves every dangling edge the moment a note with that title is written, so a `NULL` means the target really does not exist — and, the reason that survives the exception, the two directions must be one edge set read from opposite ends: a union would make an edge that `outgoing_links` reports as text read as a real backlink from the other side. The exception is pinned rather than fixed (`a_title_shared_by_two_notes_is_where_back_resolution_stops`): `notes.title` is not unique, so an edge resolved to one of two same-titled notes dangles again if *that* one is deleted, and both sides then agree it dangles. Migration `0008` is indexes only — and `idx_note_links_target` is declared **`COLLATE NOCASE`**, because back-resolution compares that way and SQLite ignores an index whose collation differs; a bare `ON note_links(target_title)` would exist, read correctly, and never be used. `the_note_link_indexes_are_the_plan_the_planner_picks` asserts the `EXPLAIN QUERY PLAN` before *and* after, since "the index is used" is the only claim an indexes-only migration can be judged on.
  - **Reflection and Review (migration `0007`).** They are **notes with a new `kind`**, not a parallel vault. The deciding argument is the graph: a reflection is meant to be the hub, and `note_links` *is* the graph — a separate table would need its own edges, its own FTS index and its own editor path, and the backlinks pane would then have to learn two vocabularies for one idea. So `notes` gains `reading_id` (nullable, `ON DELETE SET NULL`), `kind` gains `reflection`/`review`, and `UPDATE notes SET kind='reflection' WHERE kind='final'` retires the superseded one — that rewrite runs **before** the partial unique indexes `idx_one_reflection`/`idx_one_review` are created, and only applies at all because every migrated row has `reading_id IS NULL` and SQLite treats NULLs as distinct. Those two indexes make "one reflection and one review per **reading**" an invariant; `Engine::open_reflection`/`open_review` find the existing note first, which is what "accretes" means in the API. `reading_id: None` resolves through **`ensure_reading`** — the current reading, open or not, opening one only when the book has none: a reflection is written *mid-book*, and reflecting on a finished book must not start a reread. A reread therefore gets its own pair, titled `Reflection: <book> (2)` so the wikilink target does not collide with the first reading's. **No shared body**, ever — a review is a rewrite for a different audience, not a slice of the private one, and there is no `public:` key and no divider. `Engine::update_note_body` now re-indexes **wikilink edges as well as FTS** (`Storage::set_note_links`, replace-not-merge), because a reflection is opened empty and written afterwards — edges computed only at creation would leave the hub with none.
  - **Ratings and citations.** `rating_scales` (numeric only for v1: `min`/`max`/`step`), `rating_map` and `review_ratings` keep the **raw value plus the scale id**, never only the mapped integer — the map is user-editable, so the mapping has to stay re-derivable. The Goodreads mapping is an **explicit lookup, never a formula** (formulas are always wrong at the ends); `My Rating` is an integer 0–5 with no halves, so an unmapped value returns **`EngineError::UnmappedRating`** rather than a rounded one — its own variant because every caller branches on it. Migration `0007` seeds a `default` 0–5 step-0.5 scale mapped **at the whole stars only**: that is a lookup table, not a formula, and the halves are left out because 0.5 has no honest Goodreads integer. `RatingScale::step_index`/`value_at` are the **one quantizer both sides go through** — `rating_map.value` is a REAL in a PRIMARY KEY, so a lookup is float equality and `min + 3*0.1` is not the `0.3` the user typed; the bounds check carries the same tolerance, because with a fractional `min` the scale's own first point rounds to just *below* it (found by the totality property, pinned by `the_first_point_of_a_fractional_scale_is_on_its_own_scale`). Citations are **by reference** (`citations(note_id, highlight_id)`), so a review stays live across `refresh_device_fields` and "which highlights did I actually use?" is a query.
- `partial_md5.rs` — KOReader's `util.partialMD5`, computed over our own files, so our file identity agrees with the device's. MD5 over twelve 1024-byte windows at **0**, 1 Ki, 4 Ki … 1 Gi; the first offset is 0 and *not* 256, because `lshift` is LuaJIT BitOp and takes its shift count modulo 32 — `lshift(1024, -2)` is `lshift(1024, 30)`, which truncates to 0. The three checksums KOReader itself wrote are what settle that (`agrees_with_the_device`); every other test only proves we agree with ourselves. Break on a **zero-length** read, not a short one — the partial sample at EOF is hashed. It is a **sampling hash, not a content hash**: fine for dedup, sidecar↔book matching and the `statistics.sqlite3` join, wrong as a content address (sha256's job). `Engine::import_epub` hashes what it imported and records `device_books(…, linked_by = 'auto')` via `link_device_book` — never `set_device_link`, which would let a scan relabel the user's own link — so a later sidecar matches by `Md5` instead of a fuzzy title, including when KOReader keeps sidecars in `dir`/`hash` mode away from the book.
- **`ko_statistics.rs` — reading time, from the device's own statistics (item 31).** `partial_md5.rs` names "the `statistics.sqlite3` join" as one of the three things it exists for, and until this nothing did it. It is **one more filler of `reading_events`** and nothing else — day, minutes, pages, `source = 'koreader'`, `confidence = 'measured'` — so no view, no query and no line of frontend changed when it arrived, which is item 21's whole argument. There is no `reading_sessions` table and no KOReader-shaped struct on the facade. **Its own module rather than part of `device.rs`**, on that module's own logic: it reads a SQLite database rather than a tree of Lua sidecars (no shared parsing, no `find_sidecars`, no `sidecar_seen`), it joins `device_books` rather than running `match_book` (no shared matching), and it **writes**, which is the one thing `scan_device` is defined by not doing. **Not in `sync_device`'s default path** — `docs/decisions.md` makes arrival read-only, and a scan that quietly began importing months of timing data would not be read-only in spirit. `Engine::import_device_statistics` is a verb the user asks for by name.
  - **The schema was settled from KOReader's own source**, not from a device — `plugins/statistics.koplugin/main.lua`, which is the order of authority `docs/koreader-format.md` §1 established (the source is the spec; a fixture is only ever evidence). Five things it carries that the spec's description did not, each of which changed the code. **`book.md5` *is* `util.partialMD5`**, so the join is exact and no title matching happens here — and this does **not** contradict `docs/koreader-format.md` §2.1, which is about the *sidecar's* `stats` subtable; that really does carry no md5, and the statistics database is a different file. **`duration` is seconds** and **`start_time` is `os.time()`**, a true epoch. **The database is WAL**, so copying only the main file silently loses every page turn since the last checkpoint — `copy_out` takes the `-wal` and `-shm` siblings, and `rows_still_in_the_write_ahead_log_are_imported` holds a connection open across the import because SQLite checkpoints and deletes the WAL on a clean close, so a closed database would prove nothing. **`PRAGMA user_version` carries `DB_SCHEMA_VERSION`** (`20221111`), which is a real version gate rather than a guess, and an unknown value **refuses rather than guesses**: a wrong minute count is worse than none, because nothing downstream can tell it from a right one and it would ratchet `confidence` to `measured` on the way past. And a **`page_stat` VIEW exists and is deliberately unused** — it rescales pages onto the current page count, dividing `duration` by integer division and inflating a `count(DISTINCT page)`; the raw table is what the device recorded.
  - **The day skew is the correction worth carrying forward** (module doc, "The day skew"). The two KOReader sources disagree about what a timestamp *is*, and `reading_events` has one `day` column for both: a sidecar's `datetime` is zoneless local wall clock, which `ko_datetime_to_unix` reads as UTC because no offset is recorded anywhere in the file, while `page_stat_data.start_time` is a genuine `os.time()` epoch. So for **any reader not on UTC**, a session near local midnight is stamped one day by the highlight filler and the adjacent day by this one — both directions, not one hemisphere (at UTC+2 a 00:30 session, at UTC−5 a 21:00 one). **Left as-is deliberately**: shifting by a guessed offset invents data, and shifting by *this machine's* offset would make an import's result depend on where the desktop is, so re-importing on a laptop that had flown somewhere would rewrite history. The cost is bounded — an extra `inferred` row on an adjacent day, never a wrong minute count — and the honest fix is a device that records its offset, which no KOReader version does.
  - **Absence is ordinary, in four typed shapes** (`StatisticsDbAbsent`/`DbUnreadable`/`SchemaUnknown`/`BookUnmatched`/`BookNotIdentified`) — never an error and never a zero, because *zero is a claim*. Minutes round to **nearest**, so a genuine twenty-second session records `Some(0)` rather than `None`: the device is saying something, and `None` is reserved for days it never measured, which write no row at all. The distinction has a **property**, `minutes_are_absent_exactly_when_the_device_measured_nothing`, because the failure is one `unwrap_or(0)` away and looks correct in every example where a comfortable number of minutes happens to exist. Attribution goes through the **shared `READING_WINDOWS`** and leaves `reading_id` NULL when two reads both hold a day — statistics are per *file* and know nothing about rereads. **Every read of the copy sits inside one fallible region**: SQLite does not notice a file is not a database when it *opens* it, only on the first statement, so a version read outside the guard propagates a raw sqlx error out of a function whose contract is that absence is ordinary.
  - The fixture is `crates/corpus`' **`gen-kostats` (`make kostats`)**, and it emits **SQL text plus an expected-totals JSON, not a `.sqlite3`**. Both other tier-1 generators emit text and are reviewed as text; a committed database would be the one fixture nobody can read a diff of, its bytes would depend on the writer's SQLite version, and it would cost a dependency for no coverage — the engine's test materialises the script into a real database, which is where the WAL path is exercised anyway. The expected totals are accumulated **while the rows are written**, never read back, which is what makes them an oracle rather than a recording of our own aggregate query.
- **`goodreads.rs` — CSV in and out (migration `0009`).** Goodreads' API died in December 2020, so the file is the interface. `import_goodreads` / `export_goodreads` on the facade; the CLI owns every byte of output. Five things here are decisions, not mechanics. **ISBNs arrive Excel-armoured** (`="0316769487"` — a bare field with quotes in the middle of it, so the csv reader hands it over intact) and go through `strip_armour` then `normalize_isbn` like everything else. **Matching is ISBN-13 → ISBN-10 → the *same* title+author scan a sidecar gets** (`matching.rs` through `koreader::scores_for`, with the CSV's `Author` column supplying the veto side); below the band a row is reported with its candidates rather than duplicated, and `--new` is the escape hatch `ko pull` already has. **`Exclusive Shelf` maps onto `readings`** — `read` finished, `currently-reading` open, `to-read` **no reading at all**, which is why to-read needs no collection; a row with *no* shelf column (which is what our own export writes, since Goodreads' importer reads only eight columns) falls back to "a `Date Read` means it was read", without which the round trip would drop every reading. **`My Rating` is stored raw against the seeded `goodreads` scale** and never reversed through `rating_map` onto the user's own — the map is many-to-one, so its inverse is a guess; an empty cell and an explicit `0` are different cells and *neither* is a rating. `My Review` → the reading's review note (`idx_one_review` makes the re-import find it); `Private Notes` → a plain note titled for its origin, because it is neither a review nor a reflection. Prose already rewritten here is **kept**, with a `Diagnostic`, never overwritten. Idempotency is `external_ids` plus `readings_from_source`.
  - **`Read Count` is where the one real collision lives.** "Only the most recent carries `Date Read`; the rest get NULL dates" is not representable: `finished_at IS NULL` *is* what open means, and `idx_readings_one_open` permits one open reading per book. So `started_at` stays NULL on all of them (the CSV has no start date and inventing one is what this refuses) and the earlier readings close at **the same date the row already carries** — a true upper bound rather than a fabrication. With no date at all, one reading is recorded open-shaped (migration `0005`'s back-fill made the same call) and the remainder are a `Diagnostic`.
  - **Export is the eight columns Goodreads' importer reads**, ordered by what the data says (never by row id, or a re-import into an empty library would reorder itself). An **unmapped rating skips its row** and says so — a rounded star is exactly what the explicit lookup table exists to refuse — and a **reread exports its latest reading** and reports the dropped ones, because silent truncation looks like data loss on the far side. The property that covers the lot is `export → import → export is stable`, asserted into a *fresh* library.
  - **`rating_scales.is_default` (migration `0009`) is load-bearing.** `active_rating_scale()` was `ORDER BY created_at DESC`, so seeding a `goodreads` scale would have made it the scale `rating show` and `set_rating` silently default to — an import feature changing the meaning of two commands it has nothing to do with. The flag back-fills to whichever scale the old ordering would have picked, `put_rating_scale` moves it on a *new* scale only, a partial unique index makes "exactly one default" an invariant, and there is deliberately **no ordering fallback**.
  - **`book_tags` and `external_ids` are inert provenance** (`storage/provenance.rs`). Nothing reads the tags to decide anything; `docs/decisions.md` defers collections because three systems minting them is a merge problem with no good default, and the raw shelf name is kept so that design can be made against real data. `external_ids` is keyed `(source, external_id)` rather than a `goodreads_id` column because Calibre (item 13) needs the same table and the second such column is where the query that checks only one of them starts. `merge_books` repoints both — losing an `external_id` would make the next import recreate the duplicate the merge just folded in.
  - Fixtures split two ways (`crates/engine/tests/fixtures/goodreads/README.md`): **`recorded/` is hand-authored on purpose**, the documented exception to "fixtures are generated", because a Goodreads CSV is a recorded artifact of *another* system and generating one from our own understanding of the format would prove only that we agree with ourselves — same argument as the three KOReader checksums. `generated/` is `cargo run -p corpus -- gen-goodreads` (`make goodreads`) and covers volume, not shape.
- **`files.rs` — the files readingbuddy owns (item 12, migration `0010`).** Content-addressed storage at `EngineConfig::files_dir`/`<ab>/<sha256>.<ext>`; the **original filename is a column, not the path** (`book_files(sha256 PK, book_id, format, original_name, size, added_at)`), because a filename collides, changes and is somebody else's choice. `sha256` is the primary key rather than `(book_id, sha256)`, and that **is** dedup level 1 stated as a constraint: identical bytes are one file, a second import reports `AlreadyOwned` instead of succeeding, and the same content cannot hang off two books — two books holding one file means the *books* are duplicates and `merge_books` is the move. It also makes the merge's repoint a plain `UPDATE` (no collision is representable) — and that repoint is **not housekeeping**: `book_files` cascades on `books`, so leaving it would delete `src`'s rows and strand their bytes. **Level 2 is `book_id` and nothing else** (epub + azw3 = two rows, one book). **Level 3 is ISBN → `partial_md5` through the existing `device_books` table → `matching.rs`** with the same band a sidecar and a Goodreads row get (the epub's own authors when it is an epub; a file matched by its *filename stem* has none, and then the title decides alone) — **no second matcher, and no `partial_md5` column here**, since `device_books` already answers that question and a second copy would be a second answer. `import_file` **refuses to create over a candidate** and returns them with nothing written (`FileImportOptions { new: true }` is the override), the same refusal-with-a-next-move shape as `ko pull`; with no candidates at all there is nothing to refuse over, so the book is created — through `import_epub` for an epub, so there is one metadata path rather than a second worse one. `store` is **crash-safe by construction**: one pass copies and hashes into a temp file *inside* `files_dir` (same filesystem, so the `rename` is atomic) and the name is only ever a name for bytes that were fully written and flushed — a plain copy would leave, after a kill, a half file at an address claiming to be the sha256 of the whole. `format_of` **sanitizes rather than trusts**: an extension becomes a path component and arrives from downloads, devices and zips, so anything but ASCII alphanumerics is dropped and the result is always one safe component. `identify` writes nothing, so a frontend can show the answer before the user commits to it. **Engine-only for now** — no CLI or TUI surface yet; `import_epub` deliberately keeps its old behaviour and does *not* copy the file, so `rb epub` is unchanged.
- **`calibre.rs` — the two calibre tiers, through its command line (item 13).** `(i)` `ebook-convert IN OUT` and `(ii)` `calibredb list --for-machine`, on the facade as `convert_ebook` / `calibre_library` / `import_calibre_library`, with the CLI owning every byte of output. **No migration and no new dependency**: `external_ids` was made general in `0009` precisely for this, and shelling out to a GPL-3 binary is **not linking** — no licence contamination, unlike the in-process `epub =2.1.4`. **Feature-detected, never a hard dependency**: `Calibre::detect` resolves both binaries **once, at `Engine::open`** (per-book probing would be a PATH sweep per book for an answer that cannot change mid-run) over `EngineConfig::calibre_bin_dir` → `PATH` → the directories calibre installs itself in — macOS's `calibre.app` bundle adds nothing to `PATH`, so a `PATH`-only probe would miss an ordinary install. The two tools are **two `Option`s, not one flag**, so a half install degrades to the half that works. `Engine::calibre()` is a **method over a private field**, because item 14's complaint is that `storage` and `config` are public and a new subsystem must not add a third.
  - **Three traps, all found by running calibre 7.26 rather than by reading about it**, and each one would have shipped green. **`authors` is a `&`-joined string** where `tags`/`languages`/`formats` are JSON arrays (`StringOrList` accepts either). **`pubdate` is `0101-01-01T00:00:00+00:00` when undated** — calibre's `UNDEFINED_DATE`, which taken at face value gives every undated book a `publish_year` of **101**. And **`calibredb --with-library /typo list` *creates* a library there** (`metadata.db`, `.calnotes/`) and reports `[]` with exit 0, so a mistyped path is indistinguishable from an empty one and scribbles on the user's disk on the way past — `library_root` refuses a directory with no `metadata.db` **before the binary runs**, which is the only point at which refusing still helps.
  - Matching is **uuid → ISBN → `partial_md5` → the shared title+author scan** — dedup level 3 as `docs/decisions.md` states it, with calibre's own stable id in front. **uuid, never `id`**: calibre ids are per-library and reused after a delete, and `external_ids` has no library column to tell two libraries' id 4 apart. **No second matcher** — `matching.rs` with the same bands, and `--new` is the escape hatch `ko pull` and `goodreads import` already have. The scan runs **once** per row and both answers come out of it (`scores_for` then `band`); asking for the auto-match and the candidate band separately read the whole shelf twice for every row calibre listed, which on a four-hundred-book library is eight hundred loads of it. Every format calibre holds is hashed and recorded through `link_device_book` (never `set_device_link`, which would let a scan relabel the user's own link), so a sidecar off the device later matches by `Md5` instead of guessing at a title.
  - **Metadata merges with the *provider* no-clobber pattern, not the device's straight assignment**, even though `docs/decisions.md` names calibre an origin for curated metadata. The pattern is chosen by whether the record is *complete*, not by who owns it: a sidecar is the device's complete state, while a `calibredb list` row carries **no page count at all** and an empty ISBN more often than not. Correspondingly a matched book goes through **`Storage::enrich_book`, not `upsert_book`** — the latter's third branch (no `isbn_10`, no `isbn_13`) is a plain unconditional insert that ignores `Book::id`, so using it on a uuid or md5 match silently makes a second copy on **every** run. Both statements are generated from one `MERGE_RULES` table so they cannot disagree about what merging a partial record means.
  - **What the TUI shelf forced (three additions here, one on the goodreads side).** `CalibreBookReport` carries **`calibre_id`**, because a report line otherwise names its row only by *title* and two editions of one title tie to each other; **`ImportOptions::only`** filters the **listing** rather than the report, so `rows` and every count off it stay what the import considered (a user who imported one book of four hundred must not be told it read four hundred); and **`Engine::link_calibre_book`** / **`Engine::link_goodreads_row`** are the `link_sidecar` those two importers never had. Both go through one private `link_foreign_record`, kept separate from `Storage::link_external_id` because that is a bare upsert whose `book_id` FK turns a stale candidate into a raw constraint error — a frontend offering a candidate list can always name a book another pane has deleted, so it gets `EngineError::NotFound`. An empty id is refused rather than linked: calibre ids are per-library and reused after a delete, and our own Goodreads export carries no `Book Id` column at all.
  - **The rating is deliberately not imported.** `list` reports 0–10 half-stars while `set_metadata` takes 0–5, but the real reason is structural: a rating here lives on a *review*, which anchors to a *reading*, which calibre knows nothing about — importing one would mean fabricating reading history and then guessing at the explicit lookup table ratings are required to go through. Series is dropped for the same shape of reason (no column, and `book_tags` is for shelves); `external_ids` records **calibre's uuid only**, never the `goodreads` identifier calibre may also carry, because that table **repoints on conflict** and one system minting another's ids would silently redirect a later Goodreads import.
  - Tests are **fake binaries, never a real calibre**: CI has none, and a feature exercised only on the developer's laptop has no tests. `crates/engine/tests/calibre.rs` points `EngineConfig::calibre_bin_dir` at a tempdir of shell scripts — **not a `PATH` edit**, since `set_var` is `unsafe` in edition 2024 and races every other test in the binary; the `PATH` half is covered from *outside* the process in `crates/cli/tests/cli.rs`, where the environment belongs to a child. `tests/fixtures/calibre/recorded/library.json` is **recorded from calibre 7.26** — the same documented exception to "fixtures are generated" the Goodreads `recorded/` files are, and there is no `generated/` tier because a JSON array of the same shapes repeated four hundred times would test `serde_json`.
