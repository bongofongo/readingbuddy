# ui/ — the screens

One file per screen plus `mod.rs` for the shared layout. Moved here from the
root `CLAUDE.md` unchanged.

Siblings: [`../render3d/CLAUDE.md`](../render3d/CLAUDE.md) (the book object) ·
[`../../CLAUDE.md`](../../CLAUDE.md) (event loop, deferred work, ambient layer)

**`every_screen_draws_at_every_size` renders every screen from 120x40 down to
1x1 — keep it passing.** A layout panic wrecks the user's tmux pane.

- **`ui/help.rs` — the `?` page, one per screen.** A layer over the screen it describes, not a screen of its own: `App::help` is a plain `bool`, the screen underneath keeps being drawn, and **any key closes it** — a page you have to guess your way out of is the dead end it was written to prevent. It is *first* in `dispatch_key`'s chain, so no key it lists ever fires against a screen the user cannot currently see, and ctrl-c is the one exception (no layer of this app may swallow it). Each page is a short description plus its key table, and **the split is the whole design**: a screen's page lists only the keys *that screen* gives a meaning of its own, while `q`, `m`, `esc`, `j`/`k` and `?` itself live on the **menu's** page and nowhere else — repeated nine times they would bury the two or three lines that are actually news. `enter` is deliberately not on that global list: it opens, pulls, imports and adds depending on where you stand, so every page owes it a line. `no_screen_page_repeats_a_global_key` asserts the rule rather than trusting it, `page()` is exhaustive on `Screen` so a new screen cannot ship without one, and `no_page_counts_anything` keeps `docs/decisions.md`'s no-task-completion rule out of the one place a "3 of 7" would look harmless. The menu's page therefore does double duty as the app's introduction, which is right — it is the one screen about the app rather than about a book. **`?` was an alias for `o`** and is not any more: it expanded a key bar on the single screen that has one and did nothing at all on the other eight, which is the worst possible behaviour for the key everybody tries when lost. Wording is prose and prose is not assertable, so `print_help` (`cargo test -p readingbuddy-tui -- --ignored --nocapture print_help`) draws every page as text; `every_screen_draws_at_every_size` draws each one at every size, since the page is the widest box in the app.
- **`ui/home.rs` — the currently-reading screen (item 8b).** One shrink-wrapped row per **open** reading from `Engine::currently_reading`, key bar in the bottom border like the device shelf. `Enter` opens the book, `e` opens its reflection, `w` its review, `/` searches, `m` is the menu — which is the front door, with `MenuItem::Home` as this screen's first row so it is findable rather than something you have to know; `--book` and opening any book from anywhere reach it too. It **was** the front door for one release, moved there by 8b so that `Esc` on the menu could stop quitting the app — that traded one trap for another (`Esc` then quit from *here*) and the trail in [`../../CLAUDE.md`](../../CLAUDE.md) is what actually settled it, so the menu opens the app again. **Two things it must never grow: a count and a dead end.** `docs/decisions.md` bans task-completion framing by name, so nothing on the screen tallies anything (`the_home_screen_greets_you_with_no_numbers` asserts it against the drawn buffer), and the empty state names the two moves that put a book on the shelf rather than being a blank pane. The rows carry the `Reading` beside the `Book` because a sidecar-seeded book has `ko_percent` and no `current_page` at all, so `library::progress_tag` alone would leave the commonest row blank. `refresh_reading` is folded into `refresh_library` — every path that changes the shelf already funnels through there — plus the two progress mutations that do not.
- **Reflection and review are keys plus a marker in the Notes list, not two `BookTab` variants** (item 7's deferred TUI half, folded into 8b because item 8's action *is* "open the reflection"). The section menu is about collections; a reflection is a singleton, and two tabs holding one item each is the wrong shape. So `note_line` gained a one-cell kind gutter — `◆` private reflection, `◇` public review — off `NoteRecord.kind`, a column that was always loaded and never displayed; a word would only repeat the note's own title. The pair is on **`e` / `w` and not the mnemonic `r` / `v`**: those are spent on reset-pose and swap-renderer, which read correctly on the one screen the book turns on, and both the home screen and the book view need the pair — an override map two screens install identically is the global map with extra steps. Opening goes straight into `TextEditor` (there is no `$EDITOR` path here); the engine finds the existing note first, so pressing the key twice opens the same file. Saving a **review** then asks for its rating through the single-line box, the same "ask after the body" shape as a new note's page: the value goes through `RatingScale::canonical` and an off-scale one is **reported, never snapped**, as is a value the Goodreads map has no entry for.
- **`ui/device.rs` — the device screen (item 6b).** The mounted reader's own shelf, one shrink-wrapped row per book in the state `Engine::scan_device` computed (New / Unchanged / Updated / Unreadable), with the key bar in the **bottom border** so the screen can never be a dead end. `Enter` pulls the row, `x` marks, `s` syncs (marked, else every syncable row), `l` opens the engine's own candidate band, `r` rescans, `/` scans another path. Three of those keys are already spent globally (`x` export, `l` right, `r` reset), so `event::map_key_on` gives the screen a **small override map tried before `map_key`** — none of the three mean anything on a list, and renaming the global actions would read wrong on the book view. A row is a `DeviceRow` (the scan's `DeviceBook` plus this session's `note` and `notices`): this is the first surface that needs **per-row `Diagnostic`s**, since the TUI has one `status` line and flattening forty books' warnings into it says nothing about which one had the bad sidecar.
- **`ui/calibre.rs` — the calibre shelf, and `ui/goodreads.rs` — the CSV preview.** The deferred TUI halves of items 13 and 10. The calibre screen is **the device screen's shape on purpose**: calibre is another system that owns books, so the way to meet one is to be shown its shelf. One row per `calibredb list` book in the state a **dry-run import** computed (`Linked` / `New` / `Candidates` / `Unreadable`), `Enter` imports that row, `x` marks, `s` sweeps, `l` opens the candidate band, `n` is the `--new` escape hatch per row, `c` converts, `r` re-reads. **The scan is two engine calls joined on `calibre_id`** — the listing alone carries authors and the uuid *and* the rows the importer skips, so deriving the shelf from the report would silently drop every row calibre gave no title, which are the rows that most need to be visible. `s` never sweeps a `Candidates` row: that row is a question, and answering it by creating a duplicate is what the band exists to prevent.
  - Goodreads is **deliberately not a shelf**. A CSV is matched against the library as a whole and there is no per-row import to stand on, so the screen is the dry run's own report — one line per row, the undecided ones last where a cursor looking for work will find them — and `s` applies the lot. `x` keeps its **global `Export`** meaning there rather than being spent on `Mark`, because that is the one screen a Goodreads CSV is written from.
  - **One `LinkPicker` for all three importers**, keyed by a `LinkTarget` (`Sidecar` / `Calibre{uuid}` / `Goodreads{external_id}`) — the widget, the keys and the band are identical and only the engine call behind `enter` differs, so three copies would be three places for the band to drift from what the CLI offers. `commit_link` then does the work each target needs: a sidecar pulls, a calibre row imports, and a Goodreads link **re-runs the preview** (there being no single-row import), which is what makes the row visibly leave "unmatched".
  - **The clip nearly ate the next move.** `DETAIL_MAX` was 56, sized for a sidecar parse error; a candidate line composes a data-derived title *then* a fixed-length hint, and at 56 `n if not` fell off the end — a row saying what it might be and nothing about what to do, i.e. the dead end the band exists to avoid. Fixed by `ui::candidate_hint`, which budgets the **title** against what the hint leaves rather than against a second constant of its own; two constants that each look fine are how they add up past the budget together.
  - Three deferred queues, same shape as `pending_scan`/`pending_pull` and for the same reason: `calibredb list` on a real library takes seconds and a large export is thousands of rows against the matcher. `pending_calibre` is `Option<Option<PathBuf>>` — the inner `None` is calibre's *own* library, an answer rather than a missing value, which is also why `InputContext::CalibreLibrary` must be handled **before** `commit_input`'s empty-text check.
  - An **absent calibre still opens the screen**, which then explains itself: `docs/decisions.md` says absence is reported and never prescribed, and a menu row that silently does nothing is worse than a screen that says so. The wording is asserted against a forbidden-word list (`install`, `download`, `brew`, `http`…) as a **pure function**, because on a machine with calibre that branch is unreachable from outside the process — the same split the CLI's `an_absent_calibre_is_reported_and_never_prescribed` makes. For the same reason the app-level test **branches on `can_read_library()`**: `test_app` leaves `calibre_bin_dir` unset so detection falls through to `PATH`, and the developer's machine has calibre where CI does not. That unset field is also why a TUI test that *pumps* a calibre queue would otherwise run `calibredb list` against **the user's own library** — point `calibre_library` at a directory with no `metadata.db` and item 13's `library_root` guard refuses before the binary runs, which is hermetic on both machines.
  - `ebook-convert` refuses to overwrite, and the refusal is a **`Confirm`** — a TUI has no `--force` to name, and losing a file is the one outcome here with no undo. The engine reports the existing output as `InvalidInput` with no typed variant, so the string is matched exactly as the CLI matches it rather than inventing a second answer.
  - Calibre feature detection is otherwise invisible, so the **settings screen** carries one line for it (`converting and library import` / `converting only` / `library import only` / `not on this machine`). **Two tools, not one flag**: a half install degrades to the half that works.
- **The backlinks pane (item 9b) attaches to the note list, not a fifth `BookTab`.** Stand on a note in the open Notes section, press **`L`**, and `App::links` (a `LinksPane`) replaces the list in the same pane: the note's title, `N out · M in`, then one `LinkRow` per edge — outbound first, inbound after. A tab would have meant a fifth arm in four exhaustive matches and would still have had to be told *which* note it meant; the graph is consulted while standing on one (a reflection, since `docs/decisions.md` makes that the hub). **Two engine calls, never one** — `Engine::outgoing_links` + `Engine::backlinks` are the same edge set read from opposite ends, and the engine keeps them apart so neither side can claim an edge the other denies. **A dangling target is a row, rendered as text with `(no note yet)`**: a `[[wikilink]]` naming a note nobody has written is a forward reference that back-resolves later, and Enter on it *names it* rather than doing nothing. Enter on a resolved row walks the graph — into the target's book when that differs, since book-to-book connection runs reflection-to-reflection — re-selects it in the Notes list and re-centres the pane, so the walk continues. **Direction is an arrow in the text (`→` / `←`), not a colour**, so it survives the `REVERSED` selection and is what a buffer dump can be asserted on. The pane is **not modal** (nothing in `dispatch_key`'s chain): `handle_book` gives it the list's keys and leaves `n`/`space`/`t` alone, Esc backs out one level into the list it replaced, `L` toggles, and `ensure_panel` runs on every one of its keys. `reload_view` re-reads it, because saving a note rewrites its edges. **`L`, not `l`** — lowercase is the vim right and means something on every list here — and `map_key` matches both `Char('L')` and shift+`Char('l')`, since terminals disagree. The known gap 9a pinned is **rendered, not papered over**: `notes.title` is not unique, so an edge resolved to one of two same-titled notes dangles again if that one is deleted; the fix is write-side and is not this pane's.
- `ui/mod.rs::book_layout` is `{Split(PaneOrientation), Compact}`. **Split** whenever `width≥26 && height≥8`: the object + a section pane share one divider, at an orientation (`BookTop`/`BookRight`/`BookBottom`/`BookLeft`) that starts from the pane's aspect — portrait→`BookTop` (book above, panel below), landscape→`BookRight` (**panel on the left**, the new default) — and rotates clockwise per the user's `t` presses. **Tab shows/hides the section pane** (`LayoutPrefs { panel, rotation, divider_bias }` on `App`); hidden, the object owns the whole pane. Tab is no longer a tab-cycler — ↑↓ do that — and `ensure_panel` brings the pane back for ↑↓/Enter/→, which would otherwise be dead keys. `[`/`]` slide the divider (`split_rects` carves the two rects + the panel's border side). The divider rule is painted **only when a section is open** — against the bare tab menu it is a line through empty space — but its cell is reserved either way, so opening a section doesn't shift the panel. The object's default span is capped (`split_widths`/`stacked_object_height`, `BOOK_MAX_COLS=50`/`BOOK_MAX_ROWS=26` — ~20% up from the first cut) so a big pane grows the panel, not the book; `divider_bias` lets the user slide past that. Above ~98 columns the composition is **width-capped**: `content_block(area, orientation)` caps at `BOOK_MAX_COLS + PANEL_MAX_COLS` (50+48 — chosen so the two caps agree exactly, since `split_widths(98) == (50, 48)`) or `STACK_MAX_COLS=84` for a horizontal divider, and `split_rects` runs against *that* rect, so `t`/`[`/`]` keep their meaning on a smaller stage. Composing the cap **outside** `split_rects` rather than teaching it to stop tiling is what left all its existing tests valid. **`book_rects` is the book view's entry point** and composes both: the block *sizes* the object, then the object is slid so **its own centre is the window's centre**, with the panel against it on its side (capped, so the far surplus stays margin). Centring the block left the object itself parked left of centre, and the object is the centrepiece. The slide stops as soon as it would take the panel under `PANEL_MIN`, so cramped panes degrade *continuously* back to plain tiling rather than reflowing at a threshold. **Horizontal dividers pass straight through** — the stacked layout keeps its half-and-half spacing, which is what it looks best as; the book reaches the window's middle there by dismissing the pane instead. The floating header is centred over the object, and `menu_box` centres the section menu as a **block** in its pane (per-line centring would shuffle the `› ` caret column); section *content* — Info facts, notes/highlights/cards lists — stays left-aligned. Library/search instead **shrink-wrap**: `list_box(area, widest_row, rows)` sizes the box to its contents (`LIST_CHROME=6` around the widest row, `rows+2` tall) and centres it on both axes, clamped by `LIST_MIN_COLS=34`/`LIST_MAX_COLS=100`/`LIST_MIN_ROWS=7` and then by the pane — so a four-book library is a small centred box, and a long one grows to fill the height and scrolls. `print_lists` is the dev aid. **Compact** (smaller than the split gate) is the object alone, title in the border; opening a section swaps its content in where the object was. The section pane is a single-column **menu** (Info/Notes/Highlights/Cards), *not* tabs: ↑↓ move it, Enter/→ opens a section, Esc/← backs out; the book keeps spinning and the header stays put. Manual book rotation was removed (arrows drive the menu); `space` toggles spin, `r` resets pose, `t` rotates panes, tab shows/hides the section pane, `[`/`]` resize them. Text uses `Color::Reset`/`DarkGray` and `REVERSED` selection so it reads on light and dark terminals; only accents are hard-coded RGB.
