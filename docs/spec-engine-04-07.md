# Engine Spec: items 4–7

Items 1–3 are done and on `main` (`881f60f`). This spec carries the next block:
the `readings` table, `partialMD5`, the device screen, and Reflection + Review.

Four of the five threads below are engine-only. One is the first TUI work since
the positioning pass, and it is deliberately last.

All of it is held to the **Engine standards** section of `CLAUDE.md`: typed
`Diagnostic`s not strings, no silently-skipping tests, properties where an
invariant exists, no network in tests ever, fixtures generated by
`crates/corpus` rather than hand-written, tracing that never puts highlight
text, note bodies or search queries above `trace!`.

---

## Two errata before anything is planned against the build order

Items 1–3 overtook two of the entries in `docs/decisions.md`'s build order.
Both are recorded there now; they are restated here because they change what
these threads are.

**Item 5's "device→book mapping table" already exists.** `device_books` landed
with item 1b (migration `0003`), and a sidecar supplies its own
`partial_md5_checksum` at the root, already parsed into `KoSidecar.partial_md5`
(`crates/engine/src/koreader.rs:52`). What has never been built is computing the
same hash **ourselves, over a local file**. That is what makes our file identity
agree with the device's, and it is now the whole of item 5.

**Item 6 splits in two.** Its engine half — scanning a mounted device and the
mtime/size pre-filter cache — has no dependency on its TUI half. Split, the
engine half runs in parallel with item 4 instead of queueing behind it.

## Item 4 — `readings` + the progress migration

The structural one. Both item 6 and item 7 anchor to it, and every day it waits
is another day of code leaning on `books`' progress columns.

### Migration `0005_readings.sql`

```sql
CREATE TABLE readings (
    id            INTEGER PRIMARY KEY,
    book_id       INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    started_at    INTEGER,
    finished_at   INTEGER,
    status        TEXT NOT NULL DEFAULT 'reading',  -- ours: reading|finished|abandoned
    source        TEXT NOT NULL DEFAULT 'manual',   -- manual|koreader|migrated
    current_page  INTEGER,
    ko_status     TEXT,        -- device-owned mirror
    ko_percent    REAL,        -- device-owned, 0.0..=1.0
    ko_rating     INTEGER,     -- device-owned, 1..5; absent = unrated, never 0
    created_at    INTEGER NOT NULL,
    last_modified INTEGER NOT NULL
);
CREATE INDEX idx_readings_book ON readings(book_id);

-- At most one open reading per book. The invariant, not a convention.
CREATE UNIQUE INDEX idx_readings_one_open ON readings(book_id) WHERE finished_at IS NULL;

ALTER TABLE highlights ADD COLUMN reading_id INTEGER REFERENCES readings(id) ON DELETE SET NULL;
CREATE INDEX idx_highlights_reading ON highlights(reading_id);

-- Back-fill BEFORE dropping. Same migration, this order.
INSERT INTO readings (book_id, started_at, finished_at, status, source,
                      current_page, created_at, last_modified)
SELECT id, date_started, date_finished,
       CASE WHEN finished = 1 THEN 'finished' ELSE 'reading' END,
       'migrated', current_page, strftime('%s','now'), strftime('%s','now')
  FROM books
 WHERE current_page IS NOT NULL OR finished = 1
    OR date_started IS NOT NULL OR date_finished IS NOT NULL;

ALTER TABLE books DROP COLUMN current_page;
ALTER TABLE books DROP COLUMN finished;
ALTER TABLE books DROP COLUMN date_started;
ALTER TABLE books DROP COLUMN date_finished;
```

`DROP COLUMN` needs SQLite ≥ 3.35, which sqlx's bundled libsqlite3 is well past.
This is the **first destructive migration in the repo** — verify it against a
copy of a real `database/app.db`, not only against `sqlite::memory:`.

The three `ko_*` columns follow the seam item 2 established: device-owned,
refreshed by **straight assignment**, never `COALESCE`. A rating on the *user's
own* scale is a Review's (item 7); these mirror what the device said, and double
as the `last_seen_*` insurance the device-linking decision asks for.

  `crates/cli/src/commands/book.rs:88` and

### `Book` keeps its four fields as projections

This is the decision that keeps the diff small. `Book`
(`crates/engine/src/book.rs:24-27`) keeps `current_page`, `finished`,
`date_started` and `date_finished`, but they become **read-only projections of
the active reading**: `BOOK_COLUMNS` (`storage/books.rs:45-48`) stops naming
`books.*` for those four and selects them through a `LEFT JOIN` on the open
reading, falling back to the most recent reading for `finished` /
`date_finished`. `row_to_book` (`:73-76`) is then unchanged, and every consumer
keeps working untouched:

- `crates/cli/src/render.rs:9-14`, `:45-46`
- `crates/tui/src/ui/library.rs:63-83` (`progress_tag`)
- `crates/tui/src/ui/book.rs:128-140` (`progress_text`)
- `crates/cli/src/commands/note.rs:31` and `crates/tui/src/app.rs:779`
  (the note page auto-anchor)

What must change is everything that *wrote* those columns:

- **`upsert_book` (`storage/books.rs:87-154`)** — drop the four from the INSERT
  list, the set clause and the binds. **The `finished = MAX(excluded.finished,
  books.finished)` merge at `:106` disappears entirely.** It was right when
  progress lived on `books`; a provider upsert has no business touching reading
  state at all. Everything else keeps its `COALESCE` no-clobber.
- **`merge_books` (`:253-444`)** — repoint `readings.book_id` from `src` to
  `dst` inside the existing transaction, replacing the four-column fold at
  `:410-413`. Two open readings would violate the partial unique index: close
  the older one (`finished_at` = its `last_modified`, `status = 'abandoned'`)
  rather than deleting it. Respect the rule documented at `:262-264` — nothing
  inside that transaction may call back through `self`.
- **`list_books` / `BookSort::Progress` (`:186-197`)** — order by the joined
  `current_page`.

### KOReader import persists what it already parses

`BookImportStats.percent_finished` / `status` / `rating`
(`koreader.rs:421-431`) exist only because there was nowhere correct to put
them. Now there is. In `import_into` (`koreader.rs:723`), after the highlight
loop:

1. `set_device_state(book_id, …)` from `sc.summary` and `sc.percent_finished`.
2. Status mapping: `Complete` closes the active reading; `Reading` leaves it
   open; `Abandoned` sets `status = 'abandoned'`; `Other(_)` leaves ours alone —
   the `UnknownDeviceStatus` diagnostic already fires at `:739-747`.
3. `attribute_highlights(book_id)`.

Under `dry_run` none of this writes, the same rule `link_device_book` already
follows at `koreader.rs:684`.

**One thing this settles that the positioning document left open (Q27).** An
import *does* open a reading when the sidecar carries device state —
`source = 'koreader'`, started at the earliest `ko_datetime` seen. A sidecar
with neither `summary` nor `percent_finished` opens nothing, and its highlights
stay unattributed. Recorded here so it is a decision rather than an accident.

### CLI

- `progress` gains `--reread`: close the open reading, open a new one. Its

- `show` lists the reading history.

### Tests

- Back-fill round-trip: a book with progress before the migration has exactly
  one reading carrying the same values after.
- The partial unique index refuses a second open reading.
- A provider `upsert_book` never changes reading state — this asserts the

- `merge_books` moves readings and leaves exactly one open.
- Reread: finish, reopen, two readings, `Book.current_page` follows the new one.
- Each `KoStatus` maps as specified; `Other` leaves ours untouched.
- `attribute_highlights` splits by window and leaves out-of-window highlights

- `make golden`: the diff should carry **no semantic change**. The three device

## Item 5 — `partial_md5`

No migration. One new module, one dependency, one hook.

### The function

`crates/engine/src/partial_md5.rs`:

```rust
pub fn partial_md5(path: &Path) -> Result<String>;
```

From `docs/koreader-format.md` §5, quoting `frontend/util.lua:1111-1128`: MD5
over up to twelve 1024-byte samples at offsets `1024 << (2*i)` for `i = -1..10`
— **256 B, 1 Ki, 4 Ki, 16 Ki, 64 Ki, 256 Ki, 1 Mi, 4 Mi, 16 Mi, 64 Mi, 256 Mi,
1 Gi**. Output is 32-char lowercase hex.

Three details that get implemented wrong if they are not written down:

- **The first offset is 256, not 0.** `lshift(step, 2*i)` with `i = -1` is a
  right shift in Lua's bit library. The first 256 bytes of a file are never
  hashed.
- **Break on a zero-length read, not on a short one.** Lua's `file:read(size)`
  returns the partial string at EOF and that string *is* hashed; the loop ends
  on the next iteration, when the read returns `nil`. In Rust: read up to 1024
  bytes, and `break` only when 0 were read.
- **A file under 256 bytes therefore hashes to the MD5 of nothing** —
  `d41d8cd98f00b204e9800998ecf8427e`. Assert it rather than discover it.

It is a sampling hash, not a content hash: two files identical at those twelve
windows collide. That is fine for its three jobs (dedup, sidecar↔book matching,
the `statistics.sqlite3` join) and not fine as a content address, where
`docs/decisions.md` already assigns sha256.

Dependency: `md-5 = "0.10"` — RustCrypto, sibling of the already-vendored
`sha2`, shares the `digest` traits. Check `deny.toml` before writing code.

### The hook

`Engine::import_epub` (`lib.rs:202`) hashes the imported file and records
`device_books(partial_md5, book_id, linked_by = 'auto')` through
`Storage::link_device_book` (`storage/device_books.rs:54`) — the write that
**never repoints**. `set_device_link` (`:84`) is reserved for a decision the
user made, and a library scan must never relabel it.

The payoff: an epub imported here is matched by `MatchMethod::Md5` the first
time its sidecar arrives from the device — no fuzzy title guess, and no
dependence on the sidecar living beside its book (`DocSettings:getSidecarDir`
supports `dir` and `hash` modes where the sibling-epub branch cannot work).

Export `partial_md5` from `lib.rs` so item 12 has one implementation to call.

### Tests

- **Against real KOReader output.** `docs/koreader-format.md` records three
  checksums KOReader itself produced: `8cb32bca81b36ca0816851073e5661d3`
  (*To the Lighthouse*), `a5b01da92a68bbbb6d88c12483cf3b56` (*1Q84*),
  `25dc3d7e5bd746db64267cff902d3edd` (*Rust for Rustaceans*, PDF). Where the
  file exists locally, assert we agree. This is the only test that proves we
  agree with the *device*; every other test proves we agree with ourselves. It
  must print `SKIPPED:` and honour `READINGBUDDY_REQUIRE_FIXTURES=1`.
- **Property — the hash sees only its twelve windows.** Flip a byte outside
  every window: unchanged. Flip one inside: changed. This pins the algorithm
  without pinning it to our own output.
- Boundaries: 0, 255, 256, 257, 1024, exactly-on-a-sample-offset, and one file
  just over 64 Ki. Deterministic bytes (`ChaCha8Rng`, per the corpus rule) into
  a temp dir — no committed binary.
- Importing the same epub twice writes one `device_books` row and does not
  repoint an existing `manual` link.

### Done when

`make ci` green; the real-file checksums match; an epub imported here is later
matched by `md5` rather than `title`.

## Item 6a — device scan (engine)

### Where it lives

New `crates/engine/src/device.rs`. **Do not grow `koreader.rs`** — it is 1758
lines, and item 4 is editing its import path in a parallel worktree. This module
consumes `koreader::{find_sidecars, parse_sidecar, match_candidates}`, all
already public.

```rust
pub enum DeviceState {
    New { candidates: Vec<MatchCandidate> },
    Unchanged,
    Updated { new_highlights: usize, refreshed: usize },
    Unreadable(Diagnostic),
}

#[derive(Clone)]                 // the TUI buffers these, and
pub struct DeviceBook {          // BookImportStats is Debug-only
    pub path: PathBuf,
    pub title: Option<String>,
    pub authors: Option<String>,
    pub partial_md5: Option<String>,
    pub book_id: Option<i64>,
    pub matched_by: Option<MatchMethod>,
    pub state: DeviceState,
    pub ko_percent: Option<f64>,
    pub ko_status: Option<KoStatus>,
}

pub async fn scan_device(storage: &Storage, root: &Path) -> Result<DeviceScan>;
pub async fn sync_device(storage: &Storage, paths: &[PathBuf]) -> Result<Vec<PullReport>>;
pub fn candidate_mounts() -> Vec<PathBuf>;    // /Volumes/*, /run/media/$USER/*, /media/$USER/*
pub fn is_koreader_mount(p: &Path) -> bool;   // `koreader/` present with its expected contents
```

The four states are the ones `docs/decisions.md` specifies. `Unreadable` carries
the existing vocabulary — `DiagnosticKind::SidecarUnreadable` /
`SidecarUnparsable` (`diagnostic.rs:84`) — rather than inventing a parallel one.

`is_koreader_mount` is not cosmetic. The KOReader-plugin decision requires
refusing to write to an unrecognised volume, and this is the function that will
gate it. Get it right once, here, while it is still read-only.

### Migration `0006_sidecar_cache.sql`

```sql
CREATE TABLE sidecar_seen (
    path        TEXT PRIMARY KEY,   -- absolute path of the metadata.*.lua
    size        INTEGER NOT NULL,
    mtime       INTEGER NOT NULL,
    partial_md5 TEXT,
    entry_count INTEGER NOT NULL,
    last_seen   INTEGER NOT NULL
);
```

A scan today would evaluate every sidecar's Lua in mlua and then run book
matching — several hundred VM evaluations every time the screen opens. So
`stat` first, and when `(size, mtime)` match the cached row, skip the parse.

**Cache the parse, never the verdict.** A book deleted here, or linked since,
changes the state without touching the file — so the row stores only what the
*file* said, and `New`/`Unchanged`/`Updated` is recomputed from the DB on every
scan. That distinction is what stops the cache from lying after an unrelated
library edit.

`.lua.old` backups exist in 9 of 10 real `.sdr` dirs (`docsettings.lua:340`
writes one on every flush) and must never be scanned or cached — importing one
would resurrect highlights the user deleted. `is_sidecar_file`
(`koreader.rs:515`) already excludes them by suffix, incidentally. Make it
explicit and test it.

### CLI

- `rb ko scan [path]` — one line per book with its state, printed through
  plain `render.rs`-style builders.
- `rb ko sync <path> [--all | --book …]` — drives `sync_device`.

### Tests

All offline, `sqlite::memory:`, against generated fixtures.

- Each of the four states is produced by a fixture that deserves it.
- A second scan of an unmodified tree parses **zero** sidecars. Assert the
  count — a parse counter or a `tracing` span — never a timing.
- Touching a sidecar's mtime forces a re-parse; changing its bytes moves it to
  `Updated`.
- A `.lua.old` is never scanned.
- `is_koreader_mount` rejects an ordinary directory and a look-alike volume.

### Done when

`make ci` green; `rb ko scan` shows all four states against the fixture tree;
the second scan parses nothing.

## Item 6b — the device screen (TUI)

No migration. Everything it needs from the engine is `Engine::scan_device` /
`Engine::sync_device` from item 6a — the TUI never reaches into `koreader`
directly.

### The file-by-file shape

1. `app.rs:36` — `Screen::Device`.
2. `app.rs:45-88` — `MenuItem::Device` plus a `MENU` row (**the array-length
   literal `8` at `:56` must be bumped**) and an `activate_menu` arm
   (`:675-710`).
3. `App` fields: `device: Vec<DeviceBook>`, `device_state: ListState`,
   `device_marks: HashSet<usize>`, `device_root: Option<PathBuf>`.
4. `step_device`, cloned from `step_library` (`app.rs:1387-1395`).
5. New `crates/tui/src/ui/device.rs`, modelled on `library.rs:11-45`:
   `list_box` shrink-wrap, `Clear` first, `highlight_symbol("› ")`, and **no
   `highlight_style`** — the reverse goes on the title span only, which
   `search.rs:105-125` asserts.
6. `ui/mod.rs:3-10` (the `pub mod`) and `ui/mod.rs:373-379` (the draw arm).
7. `app.rs:2002-2008` (`draw_every_screen_once`) and `:2667` (`print_lists`).

### The one architectural care point

**Every engine call in the TUI is awaited inline in the key handler**
(`app.rs:1421-1461`). There is no task channel and no `tokio::spawn` anywhere in
`crates/tui/src`. A scan, or a sync of forty books, would freeze the draw loop
and the 20 fps ticker.

Copy the one existing mitigation — the deferred-work field. `pending_verify` is
set by the key handler; the loop draws the "verifying…" frame; the work is
drained *after* the redraw (`app.rs:1454-1458`, `finish_verify` at `:1155-1183`).

So: `pending_scan: Option<PathBuf>`, and `pending_pull: Option<VecDeque<PathBuf>>`
drained **one book per loop iteration with a redraw between**. That is what
gives a sync-all real per-book progress and keeps `select!` reachable — a `for`
loop inside the handler gives neither.

Diagnostics: the TUI has `status: Option<String>` and no diagnostic buffer
(`run_search` and `import_ko` both flatten to one line). This screen is the
first surface that needs per-row `Diagnostic`s, so it stores them on the row.
`Diagnostic` is `Clone` deliberately (`diagnostic.rs:31-36`).

### Keys

`Space` is `ToggleSpin` and `a` cycles the ambient motif, so: `Enter` pulls the
row, `x` marks/unmarks, `s` syncs (marked, else every `New`/`Updated`), `l`
opens the candidate list to link to an existing book, `r` rescans. The key bar
stays visible — the screen must not be a dead end.

`ambient_visible()` (`app.rs:493`) is `motif != Off && screen != Book`, so the
new screen inherits the ambient layer for free. **Do not widen `animating()`**:
it means "the book is turning", it feeds `params.moving`, and widening it makes
a parked book never transmit its crisp frame.

### Tests

- `every_screen_draws_at_every_size` (`app.rs:1973-1995`) passes with the new
  screen down to 1×1 — the usual `if inner.width == 0 || inner.height == 0
  { return; }` guard. A layout panic wrecks the user's tmux pane.
- `test_app()` (`app.rs:1546`) seeds device rows from a fixture tree.
- A sync-all drains one book per iteration: assert the queue shrinks across
  ticks, not that it completes in one.
- `print_lists` shows the new screen's rows and its REVERSED mask.

### Done when

`make ci` green; the size sweep passes; a book can be pulled from the screen,
several can be marked and synced, and an unmatched row can be linked without
leaving the screen.

## Item 7 — Reflection + Review (engine + CLI)

TUI surface is deliberately **not** in this item.

### Reuse `notes`; do not build a parallel vault

`docs/decisions.md` says both are markdown in the vault, both have a DB record,
both anchor to a reading, and only Review carries a rating. `notes` already
supplies all of that machinery: `slugify`, `frontmatter` /
`frontmatter_and_body`, `extract_wikilinks`, the `note_links` edge table with
dangling targets held as text and back-resolved, the FTS5 body cache, and
`Engine::update_note_body` / `delete_note` / `refresh_note_from_disk`.

The deciding argument is the graph. A reflection is meant to be **the hub**, and
`note_links` *is* the graph. A separate table would need its own edges, its own
FTS index and its own editor path — and the backlinks pane (item 9) would then
have to learn two vocabularies for one idea.

### Migration `0007_reflection_review.sql`

```sql
ALTER TABLE notes ADD COLUMN reading_id INTEGER REFERENCES readings(id) ON DELETE SET NULL;
CREATE INDEX idx_notes_reading ON notes(reading_id);

-- `kind` gains 'reflection' | 'review'. The old 'final' is superseded.
UPDATE notes SET kind = 'reflection' WHERE kind = 'final';

CREATE UNIQUE INDEX idx_one_reflection ON notes(reading_id) WHERE kind = 'reflection';
CREATE UNIQUE INDEX idx_one_review     ON notes(reading_id) WHERE kind = 'review';

CREATE TABLE rating_scales (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE,
    min        REAL NOT NULL,
    max        REAL NOT NULL,
    step       REAL NOT NULL,
    created_at INTEGER NOT NULL
);

-- An explicit lookup, never a formula: formulas are always wrong at the ends.
CREATE TABLE rating_map (
    scale_id  INTEGER NOT NULL REFERENCES rating_scales(id) ON DELETE CASCADE,
    value     REAL NOT NULL,
    goodreads INTEGER NOT NULL,     -- 0..5, 0 = unrated
    PRIMARY KEY (scale_id, value)
);

-- The raw value plus the scale id. Never only the mapped value: the map is
-- user-editable, so the mapping must stay re-derivable.
CREATE TABLE review_ratings (
    note_id  INTEGER PRIMARY KEY REFERENCES notes(id) ON DELETE CASCADE,
    scale_id INTEGER NOT NULL REFERENCES rating_scales(id),
    value    REAL NOT NULL
);

-- Citations by reference, so a review stays live when a highlight is refreshed.
CREATE TABLE citations (
    note_id      INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    highlight_id INTEGER NOT NULL REFERENCES highlights(id) ON DELETE CASCADE,
    created_at   INTEGER NOT NULL,
    PRIMARY KEY (note_id, highlight_id)
);
```

### Constraints that must survive the implementation

- **No shared body.** A review is written separately. It is never derived from
  the reflection — not by a `public:` frontmatter key, not by a divider. A
  public review is a rewrite for a different audience, not a subset of private
  thinking.
- **Reflections are openable mid-book and accrete.** Created with the reading,
  not at the end. That is what gives the currently-reading home screen (item 8)
  its action.
- **Rating lives on the Review only.** A reflection that wants a private score
  can have one later; it is not the same number and must not share a column.
- Goodreads' CSV `My Rating` is **integer 0–5, no halves**. Say so when a scale
  value has no mapping; never silently round.
- Numeric scales only for v1 (`min`, `max`, `step`).

### Engine

Keep `notes::create_note`'s file-and-frontmatter path as the single writer;
frontmatter gains `reading:` and the new `kind` values.

```rust
pub async fn open_reflection(&self, book_id: i64, reading_id: Option<i64>) -> Result<CreatedNote>;
pub async fn open_review(&self, book_id: i64, reading_id: Option<i64>) -> Result<CreatedNote>;
pub async fn set_rating(&self, note_id: i64, value: f64) -> Result<()>;
pub async fn cite(&self, note_id: i64, highlight_id: i64) -> Result<()>;
pub async fn citations_for(&self, note_id: i64) -> Result<Vec<Highlight>>;
pub async fn goodreads_rating(&self, note_id: i64) -> Result<Option<u8>>;
```

`open_*` create on the first call and return the existing record after — that is
what "accretes" means in the API.

### CLI

`rb reflect <book> [--reading N]`, `rb review <book> [--rating X]`,
`rb cite <note> <highlight-id>`, `rb rating scale --min --max --step`,
`rb rating map <value> <0-5>`. Body capture reuses `prompt::edit_in_editor`

- The partial unique indexes refuse a second reflection/review per reading.
- A reread gets its own pair; the first survives with its dates.
- `kind = 'final'` rows migrate to `'reflection'` keeping their `file_path`.
- Wikilinks in a reflection land in `note_links` and back-resolve — the graph
  claim, asserted rather than assumed.
- Citations survive a device refresh (highlight ids are stable — item 2 guards
  that) and cascade on highlight delete.
- Rating: the raw value round-trips; an unmapped value returns the diagnostic
  rather than a rounded integer; property — once every scale point is mapped,
  the map is a total function on the scale.

### Done when

`make ci` green; a reflection can be opened mid-book and reopened unchanged; a
rating on a user-defined scale maps to a Goodreads integer, and an unmapped one
says so.

## Order, dependencies and threads

```
4  (readings) ──┬──────────────► 7   (reflection + review)
                └──────────────► 6b  (device screen, TUI)
6a (device scan) ───────────────┘
5  (partial_md5) — independent of all three
```

| Thread | Branch | Crates | Migration |
|---|---|---|---|
| T4 | `feat/engine-readings` | engine, cli, two tui call sites | `0005` |
| T5 | `feat/engine-partial-md5` | engine | — |
| T6a | `feat/engine-device-scan` | engine, cli | `0006` |
| T6b | `feat/tui-device-screen` | tui | — |
| T7 | `feat/engine-reflection-review` | engine, cli | `0007` |

**Wave 1, in parallel: T4, T5, T6a.** **Wave 2, once T4 is merged: T6b** (also
needs T6a) **and T7.**

Why this split and not another:

- **T5 is genuinely independent** — one new module, one `Cargo.toml` line, one
  hook in `import_epub`. It touches nothing T4 or T6a touch.
- **T6a stays out of `koreader.rs`'s body**, which is what makes it safe beside
  T4, which is editing `import_into`.
- **T6b waits for T4** because the device row shows reading state and because
  both would edit `app.rs`. Two worktrees in a 2866-line file is a conflict for
  no gain.
- **T7 waits for T4** because reflections anchor to a reading. That is a foreign
  key, not a preference.

Rules for the parallel threads:

1. **Migration numbers are pre-allocated — `0005` T4, `0006` T6a, `0007` T7 —
   and branches merge in numeric order.** If T6a is green first it waits: an
   out-of-order apply against a real `database/app.db` is a footgun sqlx will
   not save you from.
2. `Cargo.toml` is touched by T5 only.
3. `crates/tui/**` is touched by T4 (two call sites) and T6b (everything else);
   T6b rebases after T4 merges rather than resolving by hand.
4. Every thread runs the `cargo-tester` agent, then `make ci`, before its PR.
5. Goldens are regenerated by T4 only, and its diff is reviewed in the PR.

Three release-mode Rust builds contend badly on one machine: cap
`CARGO_BUILD_JOBS` per worktree, or stagger the `make ci` runs. If any of this
moves off the machine, **T5 and T7 are the portable ones** — pure engine,
offline tests, no tty. T6b needs a real terminal for `print_lists` and the size
sweep.
