# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**readingbuddy** (formerly "reading_card"/"BookBuddy") is a Rust reading companion: federated book-metadata search (OpenLibrary + Google Books), epub import, KOReader highlight/note import, a markdown note vault with zettelkasten links, flashcard capture, all persisted to local SQLite. Two frontends share the engine: a thin CLI, and a ratatui TUI (designed to live in a tmux pane) whose centrepiece is a ray-traced 3D book rendered in Unicode block-glyph cells (octant/quadrant). An animated pixel companion is still to come.

See `plan.md` for the original design journal and `~/.claude/plans/` history for the 2026-07 engine redesign rationale.

**Product direction lives in `docs/decisions.md`** — what is settled, no reasoning; read it before proposing features. `docs/ux-positioning.md` is the argument behind every line of it, and `docs/spec-engine-01-03.md` + `docs/prompts/` carry the next three engine items. The design axiom is **"a place, not a tool"**: state persists and is visible, nothing is modal-by-default or a dead end, idle is not blank, and there is **no task-completion framing** — places you can go, never a badge counting what you haven't done. Data ownership is **per-field with provenance recorded**: readingbuddy keeps a durable local copy of everything but is not the *origin* of what it copies (KOReader owns highlights and reading state, calibre owns files, providers own bibliographic metadata), and conflicts resolve toward the origin.

## Commands

- Build: `cargo build --workspace`
- Test: `cargo test --workspace` (real suite: ~80 unit tests, all offline)
- Lint: `cargo clippy --workspace --all-targets`
- Run CLI: `cargo run -p readingbuddy-cli -- <subcommand>` (`--help` for the tree; `repl` for interactive mode)
- Run TUI: `cargo run -p readingbuddy-tui` (`--book <selector>` opens straight into a book)
- Inspect the 3D renderer without a TTY: `cargo run -p readingbuddy-tui -- --dump-frame 100x30 [--book X] [--pose YAW,PITCH] [--dump-png out.png]`. The PNG paints each cell exactly as the terminal would (glyph + its two colors), so it shows the quantization rather than flattering past it.
- Ask what the terminal can do (and which renderer that picks): `cargo run -p readingbuddy-tui -- --probe`. Prints the raw reply bytes too, which is the only thing that settles a surprising verdict. Needs a real tty and, inside tmux, the **active** pane.
- See the composed TUI layouts as text: `cargo test -p readingbuddy-tui -- --ignored --nocapture print_layout`
- See the ambient background as text: `cargo test -p readingbuddy-tui -- --ignored --nocapture print_ambient` (each motif at three frames). Its cost: `cargo test --release -p readingbuddy-tui -- --ignored --nocapture ambient_wire_rate`.
- Time either raster (release only, the caps depend on it): `make perf` runs all five reporting sweeps serially — `glyph_cost`, `glyph_wire_rate`, `raster_cost`, `frame_budget`, `wire_rate`. Serial matters: run in parallel they time each other's contention and the pixel traces read 20-30% slow.
- Compare what each renderer costs, terminal included: `make bench`. Needs a real, **active** pane and a book with a **real cover**; it warns rather than silently producing flattering numbers when either is missing. Output lands in gitignored `perf/`: a timestamped per-frame `.jsonl` + `.txt` summary per run, plus `history.tsv` appended one row per mode per run. `make bench-trend` prints the history aligned. `make perf` runs the release-only raster/wire-rate sweeps into the same dir. Knobs are make variables, not flags on `make`: `make bench BENCH_REPS=3` (repeat, modes interleave), `BENCH_ARGS="--book x"`. Byte columns are deterministic at one rep; **latency columns are not** — re-run a surprising one at 3 reps before believing it.
- Same comparison without giving up your terminal: **`make bench-box`** (`scripts/bench-sandbox.sh`). Runs the bench inside a disposable kitty (pinned font + window) hosting its own tmux server (`-L rbbench -f /dev/null`), against a *copy* of `database/`, so it touches neither your panes nor your library and needs no tty of yours — which is also how anything other than a person at a keyboard runs it. Refuses to start above `LOAD_MAX=2.0` (1-min load; `FORCE=1` overrides and the latency columns become suspect). **`env -u TMUX -u TMUX_PANE` is load-bearing**: inherited, they make the app DCS-wrap its queries and the fresh kitty swallows them whole, so every mode silently falls back to glyphs. Rows land in the same `history.tsv` tagged `env=box` — **trend box against box, never against `env=live`** (different font, size, neighbours). Defaults to **3 reps, and rep 1 is the terminal's warm-up**: a freshly launched kitty has never been sent an image, so `rich-always` reads 3.7ms p50 in rep 1 against 7.8-10.6ms in reps 2-3 of the same run, byte columns identical throughout. Not occlusion (reproduced with the window visible), and the in-process warm-up cannot reach it. Its acceptance test is the same calibration: if `rich-always` does not separate from `glyph` **by rep 2**, the box's latency columns are void. History also carries a `load1` column now, so a strange row stays diagnosable.
- Bulk/standardized runner: **`Makefile`** at repo root — `make test` (workspace), `make test-engine` (engine only — CI's macOS leg, and the fast inner loop), `make test-import` (KOReader harness only), `make golden` (regenerate import snapshots), `make synthetic` (regenerate the tier-1 hostile fixtures + goldens), `make goodreads` (regenerate the committed Goodreads export fixture), `make corpus` / `make corpus-check` (tier-2 Gutenberg corpus), `make lint`, `make fmt`, `make check` (fmt+lint+whole-workspace test), **`make ci`** (reproduces the CI gate exactly). Wraps `cargo-nextest` when installed, else falls back to plain `cargo test`, so nextest is never hard-required. `make help` lists targets.
- CI: `.github/workflows/ci.yml` gates PRs — fmt, `clippy --workspace --all-targets --locked -D warnings` (whole workspace, so an engine change cannot silently break CLI/TUI), nextest, and cargo-deny. The test matrix is **asymmetric on purpose**: ubuntu runs `--workspace`, macOS runs `-p readingbuddy`. The TUI suite used to be ungated on the argument that the engine is what CI gates — that only held while every TUI change was written and run by hand on the dev machine, and it contains `every_screen_draws_at_every_size`, the one thing between a layout bug and a panic in the user's pane. macOS stays engine-only because it earns its slot for the two C deps that build differently there (vendored lua54, libsqlite3-sys), not for running the ray tracer twice. `--locked` everywhere: `epub = "=2.1.4"` is pinned exactly *because* a lockfile once picked up a breaking patch release.
  - A fourth job, **`migrations`**, runs on PRs only and refuses a migration that was modified, deleted or renamed (`git diff --diff-filter=MDR` against the merge base). That is CLAUDE.md's "never edit an applied migration" as a check. Its sibling is `migration_versions_are_contiguous_from_one` in `tests/migrations.rs`: parallel branches are how two threads both claim `0008`, and a duplicate version is not a git conflict — the filenames differ past the number.
  - `scheduled.yml` carries what must not gate a PR: advisories, floating-stable clippy, and **the tier-2 corpus** (`make corpus` with `READINGBUDDY_REQUIRE_FIXTURES=1`, `corpus/epub` cached on the manifest hash). That job is overdue rather than optional — `corpus/generated` is gitignored, so on a runner every test in `tests/corpus.rs` takes its `SKIPPED:` path and asserts nothing, which is exactly how the corpus convergence bug survived item 2 and was found weeks later by a hand-run `make corpus`. Scope `READINGBUDDY_REQUIRE_FIXTURES` to that job only: set globally it fails on `real/` and on `partial_md5.rs`'s opportunistic `personal_data/` checks, both absent by design.
  - `fuzz.yml` runs weekly. The toolchain is pinned in `rust-toolchain.toml` and `Cargo.lock` is committed.

There is a `cargo-tester` agent (`.claude/agents/cargo-tester.md`) that runs fmt + clippy + tests and reports only failures — use it before committing or after touching Rust code.

## Working in a cloud session

`.claude/hooks/session-start.sh` (registered in `.claude/settings.json`) warms a fresh container: `rustup show` to force the pinned-toolchain sync, `cargo fetch --locked`, then `cargo build --workspace --tests`. It no-ops off `CLAUDE_CODE_REMOTE`. Without it the first `cargo` call also pays a toolchain download and a from-scratch build of vendored Lua and libsqlite3.

Two constraints that are worth knowing before you plan work there, because both cost a session to rediscover:

- **The sandbox proxy blocks gutenberg.org and its mirrors** (CONNECT 403), so `make corpus` — the tier-2 fixture build — cannot run in a cloud session at all. A hosted CI runner is the only machine that can build that tier; it is a `scheduled.yml` job for exactly this reason. crates.io works fine. `get.nexte.st` does not, which is why the hook does not install nextest and why the Makefile's degradation to plain `cargo test` matters.
- **The TUI suite is fully headless** and needs no terminal: it renders through ratatui's `TestBackend`. So do `--dump-frame [--dump-png]` and the `--ignored` `print_layout` / `print_lists` aids, which is how a cloud thread shows what a layout change looks like. Only `make bench`, `make bench-box` and `--probe` need a real, active pane.

## Architecture

Cargo **workspace**, three crates:

- **`crates/engine`** (lib, package name `readingbuddy`) — the engine. **Zero terminal I/O**: no `println!`, no stdin. All user interaction belongs in frontends. Errors are a typed `thiserror` enum (`EngineError`); `anyhow` is CLI-only.
  - `lib.rs` — `Engine` facade (owns `Storage`, provider list, shared `reqwest::Client`, `EngineConfig`). Frontends call this.
  - `book.rs` — `Book` domain struct + `normalize_isbn`/`isbn10_to_13`. **ISBNs are TEXT**, checksum-validated (i64 storage was a bug: leading zeros, X check digit). Identity: internal `id` canonical, ISBNs unique lookup keys.
  - `storage/` — concrete `Storage` struct over `SqlitePool`. This struct is the deliberate swap boundary (no trait until a second backend exists). `sqlx::migrate!` runs `crates/engine/migrations/` on connect; foreign keys ON per connection. Upserts keep the isbn_10 → isbn_13 → neither `ON CONFLICT` branching with `COALESCE(excluded.x, books.x)` no-clobber merging.
    - **Readings (migration `0005`).** `current_page`/`finished`/`date_started`/`date_finished` **left `books`** — that modelled one reading of one book, and rereads are real. `readings` owns them, plus a device-owned mirror (`ko_status`/`ko_percent`/`ko_rating`) refreshed by **straight assignment** like every other device field. `CREATE UNIQUE INDEX idx_readings_one_open ON readings(book_id) WHERE finished_at IS NULL` makes "at most one open reading per book" an **invariant, not a convention**; `open_reading` surfaces its violation as `EngineError::InvalidInput`, never a raw sqlx error. **`Book` keeps all four fields as read-only projections** of the *current* reading (open if there is one, else most recent), resolved by one `LEFT JOIN` in `BOOK_COLUMNS`/`BOOK_FROM` — which is what left `row_to_book`, `render.rs`, `progress_tag`, `progress_text`, the note page auto-anchor and both TUI call sites untouched. Correspondingly **`upsert_book` ignores those four fields entirely**, and its old `finished = MAX(excluded.finished, books.finished)` clause is **retired, not moved**: it only ever existed because reading state lived on `books`, and `a_provider_upsert_never_touches_reading_state` asserts its *absence* so it cannot come back. `update_progress` keeps its book-id signature and opens a reading when none is open — except when clearing `finished`, which reopens the most recent one, or the TUI's finished-toggle would mint an empty reading per keypress. `merge_books` repoints `readings.book_id` inside its transaction and **closes the older of two open readings as `abandoned`** rather than deleting it. The import persists what it had been parsing and discarding: `complete` closes the reading, `abandoned` marks it *without* closing (an abandoned book is one you might pick up), an unknown status leaves ours alone, and **`ensure_reading` opens one only when the book has *none*** — "none open" would make a `complete` sidecar add a reading on every re-import. `attribute_highlights` places a highlight by matching `ko_datetime` into a reading's window and **leaves it `NULL` when no window holds it**: KOReader's sidecar is per-file and a reread appends to it, so the device cannot supply this attribution and inventing it would be worse. Migration `0005` is the **first destructive migration in the repo** (back-fill, *then* `DROP COLUMN` ×4); `tests/migrations.rs` applies the migrations in two halves to exercise the back-fill, which a fully-migrated database can never reach.
  - `providers/` — `MetadataProvider` trait (`async_trait`, boxed): `openlibrary.rs` (search.json + /isbn/{}.json edition lookup with concurrent author-key resolution), `googlebooks.rs` (volumes?q= with `intitle:/inauthor:/inpublisher:`; API key optional via `GOOGLE_BOOKS_API_KEY`, keyless 429s degrade to warnings). Language codes normalized MARC↔BCP-47 in `providers/mod.rs`.
  - `search.rs` — federated fan-out (5s per-provider timeout, failures become warnings), dedup (canonical ISBN-13 key, else fuzzy title+author fingerprint, jaro-winkler), field-wise merge (OL wins isbn/pages, GB wins description/language), pure `rank()` (exact ISBN 1000 ≫ title 40 > author 25 > publisher 10...).
  - `koreader.rs` — parses `.sdr` sidecars by evaluating the Lua chunk in a sandboxed `mlua` VM (`StdLib::NONE`); handles modern `annotations` and legacy `highlight`+`bookmarks` formats. Imports are idempotent via sha256 identity hash (`identity_hash = sha256(book_id | ko_datetime | pos0 | text)`, `ON CONFLICT DO NOTHING`).
    - **Ownership seam (migration `0004`).** `highlights.note` is now `ko_note` (theirs) beside `annotation` (ours, never written by import) and `last_seen_ko_note` (unused today; a future two-way sync cannot tell "changed here" from "changed there" if only the merged result is ever stored). `insert_highlight` stays `DO NOTHING` — `DO UPDATE` would make `RETURNING id` yield a row on the conflict path, so `Some(id)` would stop meaning "newly inserted" and the inserted/skipped counts the goldens assert would collapse. Instead the `None` arm calls **`refresh_device_fields`**, which rewrites `ko_note`/`color`/`chapter`/`page` toward the device and returns whether anything actually changed; that boolean is `BookImportStats::updated`, and `skipped` now narrows to "present and identical". **Straight assignment, not `COALESCE`** — the books upsert's no-clobber merge is right for *providers* (partial records, missing means "don't know") and wrong here (a sidecar is the complete state, so a missing note means the user deleted it). The predicate lives once in `DEVICE_FIELDS_DIFFER` and is shared with `device_fields_differ`, so the dry-run preview cannot disagree with the import it previews. The refresh updates **in place**: `notes.highlight_id`/`flashcards.highlight_id` are foreign keys, so delete-and-reinsert would null note anchors and cascade flashcards away — guarded by `highlight_ids_are_stable_across_refresh`. Single-word highlights auto-become flashcard candidates (note: space-less CJK text counts as one "word" — see the Unicode fixture golden). Coverage lives in the data-driven harness `crates/engine/tests/koreader_import.rs` + the fixture corpus under `crates/engine/tests/fixtures/koreader/`: `synthetic/<Title>.sdr/metadata.epub.lua` cases (modern/legacy/multi-chapter/unicode/empty/malformed/unmatched) each paired with a golden JSON in `expected/` and seed books in `manifest.json`; `real/` is a **gitignored drop-in** for the user's own exports. The harness asserts golden match, strict idempotency (re-import inserts 0, no row mutates), append-only on superset re-import, and non-fatal malformed/unmatched handling. Regenerate goldens with `make golden` (`UPDATE_GOLDEN=1`).
    - **Pull from the device (item 3).** `import_book_from_sidecar` creates the book from the sidecar's own metadata (`stats` → `doc_props`/`doc_pages`; `N/A` filtered, authors newline-split) and then imports its highlights — **fully offline, no provider enrichment**, so no ISBN, cover or description. **Idempotency cannot come from `upsert_book`**: it branches isbn_10 → isbn_13 → plain unconditional insert, and a sidecar-seeded book has neither ISBN, so a second pull would create a second book. The guard is `device_books` keyed on `partial_md5`; a sidecar without one still imports but emits `DiagnosticKind::SidecarNotIdentified`, because the duplicate would otherwise appear silently much later. Matching order is **`device_books` md5 → sibling-epub ISBN → title ≥ `AUTO_MATCH` → candidate band → New**: `match_candidates` returns `CANDIDATE_MIN..AUTO_MATCH` (0.60/0.85, `const` for the same reason `PROVIDER_TIMEOUT` is), and `UnmatchedSidecar` now carries them plus the device key, so unmatched is a decision rather than a dead end. `link_sidecar` records the user's choice as `Manual` via `Storage::set_device_link`, which **repoints** — deliberately unlike `link_device_book`, which a library scan uses and which must never relabel a manual link.
    - **`Storage::merge_books`** folds a duplicate back in, and exists because the ISBN-less insert path guarantees duplicates however good matching gets. Lives in `storage/` (all SQL does), not `koreader.rs` — merging two books is not KOReader's business. **One transaction**: a half-merged library is worse than the duplicate. `book_id` is an input to a highlight's `identity_hash`, so every moved row's hash is recomputed via the shared `identity_hash_of`; a row that then collides is the *same annotation* and is **dropped, not duplicated**, after its notes and flashcards are repointed at the survivor (deleting first would cascade the flashcards away and null the note anchors). Flashcards are `UNIQUE(book_id, word)`, so shared words drop too. Field merge is `COALESCE`-style with **`dst` winning** — the inverse of `upsert_book`. `src` is deleted *before* `dst`'s fields are filled, because both ISBN columns are UNIQUE. Idempotent: a repeat merge finds `src` gone and returns `src_existed: false` with every count zero, which is what `merging_twice_equals_merging_once` asserts.
  - `device.rs` — **reading a mounted reader** (item 6a). Deliberately *not* in `koreader.rs`: a scan is not an import. `import`'s `dry_run` previews a tree, but it evaluates every sidecar's Lua in mlua first — several hundred VM runs every time the screen opens — and answers "what would import" rather than "what state is each book in". `scan_device` is read-only and returns a `DeviceState` per book (**New{candidates} / Unchanged / Updated{new,refreshed} / Unreadable(Diagnostic)** — the four `docs/decisions.md` names, with the existing `SidecarUnreadable`/`SidecarUnparsable` vocabulary rather than a parallel taxonomy); `sync_device` writes, one `PullReport` per book so a frontend can show per-book progress. `is_koreader_mount`/`koreader_dir` know all three install layouts (`koreader/` Kindle, `.adds/koreader` Kobo, `applications/koreader` PocketBook) and require `reader.lua` + `frontend/` + `plugins/` inside — **not cosmetic**: this is the gate that will refuse to install the plugin onto an unrecognised volume.
    - **The pre-filter cache — `sidecar_seen`, migration `0006`.** `stat` first; when `(size, mtime)` match the cached row the parse is skipped. **It caches the parse, never the verdict** — a book deleted here, or linked since, changes a sidecar's state without touching the file, so New/Unchanged/Updated is recomputed from the DB every scan. Every column is something the *file* said, which is why `title`/`authors`/`ko_percent`/`ko_status` live there too: without them a cache hit could not be matched or displayed and would have to re-parse, i.e. do nothing. `title` is `doc_props.title` **exactly**, because it is fed back to `koreader::match_book` (made `pub` for this) and a cache hit must reach the verdict a fresh parse would. `mtime` is **nanoseconds**: a device flushes on every page turn and two edits in one second are ordinary.
    - **The cheap path compares a digest, not a row count.** A count was the first cut and is wrong: a note rewritten on the device leaves it identical, so the edit was reported by the one scan that re-read the file and by no scan after it — the cache then said "unchanged" forever about a change it had already seen. `sidecar_seen.entry_digest` and `Storage::device_highlight_digest` both go through **`DeviceDigest`** (identity + the four device-owned fields, `annotation` deliberately absent, sorted in `finish` so neither side owes an ordering) — one formula, same rule as `identity_hash_of` and `DEVICE_FIELDS_DIFFER`.
    - The prune of vanished sidecars compares `last_seen <> token`, **not `< started`**: at second resolution a scan finishing in the same second as the last one prunes nothing and never fails. One nanosecond token per scan, stamped on every row it touches. Scoped by path prefix via `substr`, not `LIKE` (a `%` in a volume name is a wildcard) and with the separator appended (`/mnt/a` is not a prefix of `/mnt/abc`).
    - A sidecar that does not parse is **not cached** — every column is what the file said, and it said nothing — so it is re-read each scan. That is the right price for the one or two a real device has, and it is why "a second scan parses zero" is asserted over a tree of valid sidecars.
  - `notes.rs` — vault of markdown files (`vault/<book-slug>/<timestamp>-<slug>.md`, hand-rolled frontmatter, Obsidian-openable). A note anchors to a book plus optional `page`/`location`/`highlight_id` (migration `0002`); `frontmatter_and_body` splits the raw header from the body so `Engine::update_note_body` can rewrite the body while preserving frontmatter. DB keeps metadata + `note_links` (wikilink edges, dangling targets kept as text and back-resolved) + FTS5 index (ordinary fts5 table as searchable body cache; delete+insert on save). `delete_note` removes the vault file + row + edges; the FTS row must be `DELETE`d explicitly (a virtual table can't be reached by a foreign-key cascade), while `note_links` do cascade (from_note CASCADE, to_note SET NULL → links pointing at a deleted note degrade to dangling text).
    - **Walking the graph (migration `0008`).** `Storage::backlinks` ("what links here") and `Storage::outgoing_links` (the same edges plus the target row) are the two directions, surfaced on the facade as `Engine::backlinks`/`Engine::outgoing_links` and by `rb links <note>`; before this the facade exposed no link method at all. **`backlinks` is a plain `WHERE to_note = ?`, deliberately without a dangling-by-title union.** `write_links` back-resolves every dangling edge the moment a note with that title is written, so a `NULL` means the target really does not exist — and, the reason that survives the exception, the two directions must be one edge set read from opposite ends: a union would make an edge that `outgoing_links` reports as text read as a real backlink from the other side. The exception is pinned rather than fixed (`a_title_shared_by_two_notes_is_where_back_resolution_stops`): `notes.title` is not unique, so an edge resolved to one of two same-titled notes dangles again if *that* one is deleted, and both sides then agree it dangles. Migration `0008` is indexes only — and `idx_note_links_target` is declared **`COLLATE NOCASE`**, because back-resolution compares that way and SQLite ignores an index whose collation differs; a bare `ON note_links(target_title)` would exist, read correctly, and never be used. `the_note_link_indexes_are_the_plan_the_planner_picks` asserts the `EXPLAIN QUERY PLAN` before *and* after, since "the index is used" is the only claim an indexes-only migration can be judged on.
    - **Reflection and Review (migration `0007`).** They are **notes with a new `kind`**, not a parallel vault. The deciding argument is the graph: a reflection is meant to be the hub, and `note_links` *is* the graph — a separate table would need its own edges, its own FTS index and its own editor path, and the backlinks pane would then have to learn two vocabularies for one idea. So `notes` gains `reading_id` (nullable, `ON DELETE SET NULL`), `kind` gains `reflection`/`review`, and `UPDATE notes SET kind='reflection' WHERE kind='final'` retires the superseded one — that rewrite runs **before** the partial unique indexes `idx_one_reflection`/`idx_one_review` are created, and only applies at all because every migrated row has `reading_id IS NULL` and SQLite treats NULLs as distinct. Those two indexes make "one reflection and one review per **reading**" an invariant; `Engine::open_reflection`/`open_review` find the existing note first, which is what "accretes" means in the API. `reading_id: None` resolves through **`ensure_reading`** — the current reading, open or not, opening one only when the book has none: a reflection is written *mid-book*, and reflecting on a finished book must not start a reread. A reread therefore gets its own pair, titled `Reflection: <book> (2)` so the wikilink target does not collide with the first reading's. **No shared body**, ever — a review is a rewrite for a different audience, not a slice of the private one, and there is no `public:` key and no divider. `Engine::update_note_body` now re-indexes **wikilink edges as well as FTS** (`Storage::set_note_links`, replace-not-merge), because a reflection is opened empty and written afterwards — edges computed only at creation would leave the hub with none.
    - **Ratings and citations.** `rating_scales` (numeric only for v1: `min`/`max`/`step`), `rating_map` and `review_ratings` keep the **raw value plus the scale id**, never only the mapped integer — the map is user-editable, so the mapping has to stay re-derivable. The Goodreads mapping is an **explicit lookup, never a formula** (formulas are always wrong at the ends); `My Rating` is an integer 0–5 with no halves, so an unmapped value returns **`EngineError::UnmappedRating`** rather than a rounded one — its own variant because every caller branches on it. Migration `0007` seeds a `default` 0–5 step-0.5 scale mapped **at the whole stars only**: that is a lookup table, not a formula, and the halves are left out because 0.5 has no honest Goodreads integer. `RatingScale::step_index`/`value_at` are the **one quantizer both sides go through** — `rating_map.value` is a REAL in a PRIMARY KEY, so a lookup is float equality and `min + 3*0.1` is not the `0.3` the user typed; the bounds check carries the same tolerance, because with a fractional `min` the scale's own first point rounds to just *below* it (found by the totality property, pinned by `the_first_point_of_a_fractional_scale_is_on_its_own_scale`). Citations are **by reference** (`citations(note_id, highlight_id)`), so a review stays live across `refresh_device_fields` and "which highlights did I actually use?" is a query.
  - `partial_md5.rs` — KOReader's `util.partialMD5`, computed over our own files, so our file identity agrees with the device's. MD5 over twelve 1024-byte windows at **0**, 1 Ki, 4 Ki … 1 Gi; the first offset is 0 and *not* 256, because `lshift` is LuaJIT BitOp and takes its shift count modulo 32 — `lshift(1024, -2)` is `lshift(1024, 30)`, which truncates to 0. The three checksums KOReader itself wrote are what settle that (`agrees_with_the_device`); every other test only proves we agree with ourselves. Break on a **zero-length** read, not a short one — the partial sample at EOF is hashed. It is a **sampling hash, not a content hash**: fine for dedup, sidecar↔book matching and the `statistics.sqlite3` join, wrong as a content address (sha256's job). `Engine::import_epub` hashes what it imported and records `device_books(…, linked_by = 'auto')` via `link_device_book` — never `set_device_link`, which would let a scan relabel the user's own link — so a later sidecar matches by `Md5` instead of a fuzzy title, including when KOReader keeps sidecars in `dir`/`hash` mode away from the book.
  - **`goodreads.rs` — CSV in and out (migration `0009`).** Goodreads' API died in December 2020, so the file is the interface. `import_goodreads` / `export_goodreads` on the facade; the CLI owns every byte of output. Five things here are decisions, not mechanics. **ISBNs arrive Excel-armoured** (`="0316769487"` — a bare field with quotes in the middle of it, so the csv reader hands it over intact) and go through `strip_armour` then `normalize_isbn` like everything else. **Matching is ISBN-13 → ISBN-10 → the *same* jaro-winkler title scan a sidecar gets** (`koreader::title_scores_for`, `AUTO_MATCH`/`CANDIDATE_MIN` unchanged); below the band a row is reported with its candidates rather than duplicated, and `--new` is the escape hatch `ko pull` already has. **`Exclusive Shelf` maps onto `readings`** — `read` finished, `currently-reading` open, `to-read` **no reading at all**, which is why to-read needs no collection; a row with *no* shelf column (which is what our own export writes, since Goodreads' importer reads only eight columns) falls back to "a `Date Read` means it was read", without which the round trip would drop every reading. **`My Rating` is stored raw against the seeded `goodreads` scale** and never reversed through `rating_map` onto the user's own — the map is many-to-one, so its inverse is a guess; an empty cell and an explicit `0` are different cells and *neither* is a rating. `My Review` → the reading's review note (`idx_one_review` makes the re-import find it); `Private Notes` → a plain note titled for its origin, because it is neither a review nor a reflection. Prose already rewritten here is **kept**, with a `Diagnostic`, never overwritten. Idempotency is `external_ids` plus `readings_from_source`.
    - **`Read Count` is where the one real collision lives.** "Only the most recent carries `Date Read`; the rest get NULL dates" is not representable: `finished_at IS NULL` *is* what open means, and `idx_readings_one_open` permits one open reading per book. So `started_at` stays NULL on all of them (the CSV has no start date and inventing one is what this refuses) and the earlier readings close at **the same date the row already carries** — a true upper bound rather than a fabrication. With no date at all, one reading is recorded open-shaped (migration `0005`'s back-fill made the same call) and the remainder are a `Diagnostic`.
    - **Export is the eight columns Goodreads' importer reads**, ordered by what the data says (never by row id, or a re-import into an empty library would reorder itself). An **unmapped rating skips its row** and says so — a rounded star is exactly what the explicit lookup table exists to refuse — and a **reread exports its latest reading** and reports the dropped ones, because silent truncation looks like data loss on the far side. The property that covers the lot is `export → import → export is stable`, asserted into a *fresh* library.
    - **`rating_scales.is_default` (migration `0009`) is load-bearing.** `active_rating_scale()` was `ORDER BY created_at DESC`, so seeding a `goodreads` scale would have made it the scale `rating show` and `set_rating` silently default to — an import feature changing the meaning of two commands it has nothing to do with. The flag back-fills to whichever scale the old ordering would have picked, `put_rating_scale` moves it on a *new* scale only, a partial unique index makes "exactly one default" an invariant, and there is deliberately **no ordering fallback**.
    - **`book_tags` and `external_ids` are inert provenance** (`storage/provenance.rs`). Nothing reads the tags to decide anything; `docs/decisions.md` defers collections because three systems minting them is a merge problem with no good default, and the raw shelf name is kept so that design can be made against real data. `external_ids` is keyed `(source, external_id)` rather than a `goodreads_id` column because Calibre (item 13) needs the same table and the second such column is where the query that checks only one of them starts. `merge_books` repoints both — losing an `external_id` would make the next import recreate the duplicate the merge just folded in.
    - Fixtures split two ways (`crates/engine/tests/fixtures/goodreads/README.md`): **`recorded/` is hand-authored on purpose**, the documented exception to "fixtures are generated", because a Goodreads CSV is a recorded artifact of *another* system and generating one from our own understanding of the format would prove only that we agree with ourselves — same argument as the three KOReader checksums. `generated/` is `cargo run -p corpus -- gen-goodreads` (`make goodreads`) and covers volume, not shape.

- **`crates/tui`** (bin `readingbuddy-tui`) — the ratatui frontend. Screens: **home** → menu → (library list | search | device | settings) → single-book view. The menu carries the global/CLI actions (search+add, add-by-ISBN, KOReader import, device, settings, remove-from-library). `m` returns to the menu from anywhere; the book view's key bar is always present (`o` expands it — never hide it entirely, or the view becomes a dead end). Modal input flows layer on top of any screen and are routed in `app::dispatch_key` in priority order `note_editor → input → confirm → map_key_on`: `ui/textedit.rs` is the in-house multi-line note editor (Enter saves, Esc cancels, Shift/Alt+Enter or Ctrl-J = newline — **there is no `$EDITOR`/suspend path**, deliberately, after a broken vim killed the TUI); `ui/input.rs` is a single-line box (search query, ISBN, progress page, the optional note-page prompt). Notes anchor to a `page`/`location`/`highlight` — the CLI auto-fills page from `current_page`, the TUI asks after the body (empty/invalid/Esc = no page).
  - **`ui/home.rs` — the currently-reading screen (item 8b), and what the app opens to.** One shrink-wrapped row per **open** reading from `Engine::currently_reading`, key bar in the bottom border like the device shelf. `Enter` opens the book, `e` opens its reflection, `w` its review, `/` searches, `m` is the menu — which is *no longer the front door*, so `Esc` on the menu comes back here instead of quitting, and `MenuItem::Home` keeps the screen findable rather than something you have to know. **Two things it must never grow: a count and a dead end.** `docs/decisions.md` bans task-completion framing by name, so nothing on the screen tallies anything (`the_home_screen_greets_you_with_no_numbers` asserts it against the drawn buffer), and the empty state names the two moves that put a book on the shelf rather than being a blank pane. The rows carry the `Reading` beside the `Book` because a sidecar-seeded book has `ko_percent` and no `current_page` at all, so `library::progress_tag` alone would leave the commonest row blank. `refresh_reading` is folded into `refresh_library` — every path that changes the shelf already funnels through there — plus the two progress mutations that do not.
  - **Reflection and review are keys plus a marker in the Notes list, not two `BookTab` variants** (item 7's deferred TUI half, folded into 8b because item 8's action *is* "open the reflection"). The section menu is about collections; a reflection is a singleton, and two tabs holding one item each is the wrong shape. So `note_line` gained a one-cell kind gutter — `◆` private reflection, `◇` public review — off `NoteRecord.kind`, a column that was always loaded and never displayed; a word would only repeat the note's own title. The pair is on **`e` / `w` and not the mnemonic `r` / `v`**: those are spent on reset-pose and swap-renderer, which read correctly on the one screen the book turns on, and both the home screen and the book view need the pair — an override map two screens install identically is the global map with extra steps. Opening goes straight into `TextEditor` (there is no `$EDITOR` path here); the engine finds the existing note first, so pressing the key twice opens the same file. Saving a **review** then asks for its rating through the single-line box, the same "ask after the body" shape as a new note's page: the value goes through `RatingScale::canonical` and an off-scale one is **reported, never snapped**, as is a value the Goodreads map has no entry for.
  - **`ui/device.rs` — the device screen (item 6b).** The mounted reader's own shelf, one shrink-wrapped row per book in the state `Engine::scan_device` computed (New / Unchanged / Updated / Unreadable), with the key bar in the **bottom border** so the screen can never be a dead end. `Enter` pulls the row, `x` marks, `s` syncs (marked, else every syncable row), `l` opens the engine's own candidate band, `r` rescans, `/` scans another path. Three of those keys are already spent globally (`x` export, `l` right, `r` reset), so `event::map_key_on` gives the screen a **small override map tried before `map_key`** — none of the three mean anything on a list, and renaming the global actions would read wrong on the book view. A row is a `DeviceRow` (the scan's `DeviceBook` plus this session's `note` and `notices`): this is the first surface that needs **per-row `Diagnostic`s**, since the TUI has one `status` line and flattening forty books' warnings into it says nothing about which one had the bad sidecar.
  - **The backlinks pane (item 9b) attaches to the note list, not a fifth `BookTab`.** Stand on a note in the open Notes section, press **`L`**, and `App::links` (a `LinksPane`) replaces the list in the same pane: the note's title, `N out · M in`, then one `LinkRow` per edge — outbound first, inbound after. A tab would have meant a fifth arm in four exhaustive matches and would still have had to be told *which* note it meant; the graph is consulted while standing on one (a reflection, since `docs/decisions.md` makes that the hub). **Two engine calls, never one** — `Engine::outgoing_links` + `Engine::backlinks` are the same edge set read from opposite ends, and the engine keeps them apart so neither side can claim an edge the other denies. **A dangling target is a row, rendered as text with `(no note yet)`**: a `[[wikilink]]` naming a note nobody has written is a forward reference that back-resolves later, and Enter on it *names it* rather than doing nothing. Enter on a resolved row walks the graph — into the target's book when that differs, since book-to-book connection runs reflection-to-reflection — re-selects it in the Notes list and re-centres the pane, so the walk continues. **Direction is an arrow in the text (`→` / `←`), not a colour**, so it survives the `REVERSED` selection and is what a buffer dump can be asserted on. The pane is **not modal** (nothing in `dispatch_key`'s chain): `handle_book` gives it the list's keys and leaves `n`/`space`/`t` alone, Esc backs out one level into the list it replaced, `L` toggles, and `ensure_panel` runs on every one of its keys. `reload_view` re-reads it, because saving a note rewrites its edges. **`L`, not `l`** — lowercase is the vim right and means something on every list here — and `map_key` matches both `Char('L')` and shift+`Char('l')`, since terminals disagree. The known gap 9a pinned is **rendered, not papered over**: `notes.title` is not unique, so an edge resolved to one of two same-titled notes dangles again if that one is deleted; the fix is write-side and is not this pane's.
  - **Deferred work: `pending_scan` / `pending_pull`, drained by the loop, never the key handler.** Every other engine call in this crate is awaited inline in `dispatch_key`, which is fine for a lookup and ruinous for a scan of several hundred sidecars or a sync of forty books — the draw loop and the 20fps ticker would both stop. `App::pump_deferred` does **one unit per loop iteration** (verify → scan → one book of the pull queue), and `run` calls it *after* the redraw, so the frame that says "scanning…" / "bringing 12 books across…" is on screen before the work that blocks. `select!` gained `biased` plus a `std::future::ready(())` arm guarded on `has_deferred()`: without it the queue would advance one book per 50ms tick, and without `biased` a keypress would stop being seen first. A `for` loop in the handler gives neither the progress nor the reachable `select!`. Guarded by `a_sync_drains_one_book_per_iteration`, which asserts the queue *shrinks across pumps* rather than completing in one.
  - **`animating()` is not widened for this screen either** — same rule as the ambient layer. The device screen inherits the ambient background for free from `ambient_visible()` (`motif != Off && screen != Book`), which is exactly why its list box and its candidate chooser both `Clear` first.
  - `render3d/` — the book object. **No rasterizer**: the book is one cuboid, so `scene.rs` builds a camera ray per subpixel, pulls it into local space with the transposed rotation, and runs a slab intersection — the winning axis names the face, the other two local coords are the UV. Faces: cover texture / accent spine + back / cream page edges striped along local Z. `Model` (in `mod.rs`) takes the front face's aspect from the cover image (so covers are never stretched) and the thickness from `page_count`. Lighting is key + fill + ambient — the fill exists so the back cover isn't a black hole every time the 360° spin brings it round.
  - The book turns about its own centre, ~27s per revolution. `Pose::default` tips it back (negative pitch) so the cover faces upward and the bottom page edges show; positive pitch would face the cover down instead.
  - `camera_distance` fits by projecting the 8 corners over a full yaw sweep, so scale stays constant through a whole turn rather than breathing in and out. `scene::fill_for(rows)` slides the fill fraction from 0.88 on a small pane down to 0.60 on a big one: this caps the object's *absolute* size instead of letting it track the window. Raising it makes the book too big on a full terminal — that was fixed once already.
  - `blit.rs` quantizes a cell's subpixels into one block glyph, over a selectable `GlyphSet`: **Quadrant** (2x2, sixteen glyphs U+2580..U+259F) or the default **Octant** (2x4, Unicode 16 mosaics U+1CD00.. plus reused block/quarter glyphs — 2× vertical resolution). A cell holds two colors, so it tries every split and keeps the lowest squared error; where a cell straddles the silhouette the split is forced by coverage, which buys subcell edges instead of whole-column stair-steps. `None` subpixels emit `Color::Reset`, so the pane keeps the user's terminal background. The **octant mask→char table is generated from the Unicode 16 UCD, not hand-written** (230 masks map to dedicated code points, 26 reuse scattered legacy glyphs); `octant_masks_round_trip` guards it — never hand-edit. Octants need a Unicode-16 font (else tofu), so `--glyphs quadrant` is a first-class fallback on both the TUI and `--dump-frame`.
  - Backends behind the `BookPresenter` seam (`render3d/present.rs`), picked by `RenderMode` (`render3d/mod.rs`): **`Glyph`** (block glyphs, works anywhere truecolor does), **`Rich`** — the **hybrid**: glyphs while the book turns, true RGBA pixels (kitty graphics) the moment it parks — and **`RichAlways`** (pixels even while moving; see below). Rich is **not** gated to non-tmux — kitty graphics survive tmux via DCS passthrough, measured. `v` toggles live in the book view; `--render auto|glyph|rich|rich-always`, and `auto` picks Rich wherever `Caps::supports_pixels()`.
  - **No images while animating. Not a budget — a zero.** A byte of image costs a terminal far more than a byte of text (decompress + whole-texture re-upload + recomposite), so no resolution or throttle setting makes an animated pixel book as cheap as glyphs; two rounds of tuning proved it and **there must not be a third**. `RichPresenter` hands every moving frame to `GlyphPresenter`, deleting the image first; only a parked pose transmits, once, at `SETTLE_MAX_PX`. Measured: glyph spin 0.09 MB/s at 50x26, 0.13 MB/s on a full pane. Guarded by `a_moving_book_sends_no_image_bytes_at_all` and `the_hybrid_costs_no_more_than_glyphs_while_moving`.
  - **Motion is told, not inferred.** `RenderParams::moving` is set by `App` from `App::animating()` (the same guard `tick` uses). The old pose-comparison inference is the fallback when it is `None` (`--dump-frame`, unit tests) and is *wrong* for the hybrid: a parked book stops redrawing entirely, so there is no second draw in which to notice it parked. Correspondingly, `RichState::hide_image` (per-transition) must not clear `last_pose`/placeholders — only `drop_image` (leaving rich mode) does the full reset.
  - **`RichAlways` is deliberately-kept known-bad code**, reachable only by `--render rich-always`. It is what the terminal-latency instrument is calibrated against — an instrument that has never seen the failure it exists to catch is not evidence of anything. **Calibration passes, measured**: kitty RTT p90 9.1/9.1/10.6ms for `rich-always` against 3.5-4.3ms for both `glyph` and `rich`, reproducible over 3 reps with no overlap. `MOTION_Q`/`MOTION_MAX_PX` and `a_spinning_book_retransmits_well_below_the_tick_rate` exist to keep it bad-but-survivable.
  - **`render3d/caps.rs`** probes the terminal once, inside `setup_terminal` (raw mode on, alt screen entered, before ratatui reads input — that ordering is what stops reply bytes leaking into the later `EventStream`). Sends `_Ga=q` + `CSI 16 t` (tmux-wrapped) plus **`CSI c` unwrapped as a sentinel**: tmux answers DA1 locally, so "DA1 but no `_G`" is a definitive no rather than a timeout. Replies arrive *out of order* (tmux's DA1 first), hence the grace period. tmux routes input to the **active pane only**, so probing a background pane false-negatives to glyph — safe, and overridable. `--probe` prints the verdict plus the raw reply bytes.
  - tmux `allow-passthrough` is a **pane** option: the app sets it on its own pane and restores it on exit + panic, never touching the user's `tmux.conf`. The debt and the live image id are **atomics, not mutexes** — the panic hook must never deadlock on a lock the panicking thread holds.
  - **Placement is ordinary buffer cells, not escapes**: `U+10EEEE` + row/col combining diacritics, image id in the fg colour (`render3d/kitty.rs`). That is why layout, `t`, `[`/`]`, resize and the floating header all work unchanged — the header just overwrites placeholder cells. **Always emit both diacritics**; kitty's run-continuation shorthand is unusable because ratatui's `Buffer::diff` emits non-contiguous runs. Image ids stay under 2^24 so the third diacritic is never needed. The diacritic table is **generated from the file inside kitty.app, not hand-written** (`diacritic_table_is_intact` guards it) — same rule as the octant table. A placeholder cell must measure width 1 or the diff skips every other cell; asserted, not assumed.
  - **`render3d/raster.rs`** is a second raster beside `render`, never a replacement — that is what keeps `--dump-frame` byte-identical by construction. The glyph majority-hit rule is right for glyphs but jaggy for pixels, so this path carries real alpha. AA is one ray/pixel plus a re-trace of only the silhouette (perimeter is O(√N), so it costs <1%). Both rasters go through `scene::camera_origin` → `fill_for(rows)`, the sole authority on the object's absolute size — the book must not grow just because it has more pixels. Resolution is native cell res capped at **0.12 MP while moving / 1.2 MP when settled**; the tier is chosen by comparing the pose to the last draw's, so no event-loop plumbing.
  - **The motion cap and the retransmit throttle are load-bearing, not tuning.** At 0.42 MP/20fps this streamed 7.1 MB/s and made the terminal unusable — and *none of our own numbers show it*: trace+encode is a few ms and `write`/`flush` never blocks (a bench sustains 270 fps / 27 MB/s). The cost is inside the terminal, which re-uploads the whole texture per frame while tmux re-parses it. So `present.rs` quantizes the pose **two ways**: a fine quantum (1/512 rad) detects "still moving", a coarse one (`MOTION_Q`, 1/32 rad) is the transmit cache key while moving — consecutive ticks share a bucket, so a spinning book retransmits at ~7fps and a skipped frame costs no CPU either (the trace lives inside the transmit). Net ~0.8 MB/s — still too much, which is why `Rich` no longer animates in pixels at all and this machinery now serves `RichAlways` only. Measure in a real pane and with a **real cover** — a procedural cover compresses several times better and will flatter the numbers.
  - **`crates/tui/src/perf.rs` is the cost accounting**, and it exists because our own numbers did not show the 7.1 MB/s disaster. `CountingWriter` wraps *both* the ratatui backend (text bytes) and the graphics writer (image bytes) — the split is the point, and wrapping the backend is the only way the glyph path is measurable at all. Stage timings go through a thread-local scratchpad (`perf::scope`), not a parameter, because `present_book` depends on disjoint direct-field borrows of `App`. Inert unless `--perf-log PATH`/`READINGBUDDY_PERF_LOG` is set (one relaxed atomic load).
  - **`caps::rtt_probe` is the honest instrument**: time the terminal's reply to a wrapped `_Ga=q` (the outer terminal's queue) and a bare `CSI c` (tmux's, answered locally) *while under load*. A drowning terminal answers slowly. **Bench-mode only** — it consumes stdin, which a live session hands to `EventStream`.
  - **`--bench-render <glyph|rich|rich-always|all>`** drives the real presenter through a real `Terminal::draw` (so the throttle, placeholder cells and ratatui diff all count) over a fixed script, and reports bytes/s by class, sends, and RTT percentiles. `make bench`. The column that matters is **moving-KB**; for the hybrid it is 0. `--bench-rich` still exists but bypasses `present.rs`, so it measures the raster alone.
  - Glyph framebuffer is `cols * 2` x `rows * glyphs.cell_h()` (cell_h 2 for quadrant, 4 for octant); the *physical* aspect `primary_ray` takes is `cols / (rows * 2)` — the cell grid's shape, not the sample grid's. The pixel path passes the true `width/height` instead. Default supersampling is `ss = 3`.
  - `Scene` caches the decoded cover (per book + texel target — `Scene::cover(book, texels)` is shared, the pixel path asks for more) and the last glyph frame (`FrameKey`: cover, quantized pose, cols, rows, **ss and glyph set**; the last two matter because `glyphs` fixes the framebuffer height). The rich path keeps its own cache in `RichState`. The 20fps tick only re-traces when something moved. Judge performance on a release build (debug ~30x slower). Cover paths are relative to the data root, resolved against `EngineConfig::images_dir`.
  - **A resize invalidates the transmitted frame** (`RichState::resized`, called from `app::redraw` — the one funnel that sees both every draw and the terminal size). The transmit cache is keyed on the *object rect*, and in a stacked layout both of that rect's axes are capped (`STACK_MAX_COLS`, `BOOK_MAX_ROWS`), so resizing the window routinely leaves it identical: the key still matched, nothing was re-sent, and the terminal — which drops or misplaces images across a resize, tmux especially — was left showing half a book or none. The side-by-side layouts hid it, since their object takes the full pane height and any vertical resize changes the key. `RichKey` also carries the rect's `x`/`y`, so a frame that merely *moved* re-sends too, and a **span change deletes before transmitting** rather than writing over a placement whose geometry is stale. Guarded by `a_resize_retransmits_the_parked_image`.
  - Images **must** be deleted or they ghost: `kitty::teardown()` is the *first* step of `restore_terminal` (before leaving the alt screen, where the placement lives), inherited by the panic hook, and also fired when `v` leaves rich mode.
  - **`crates/tui/src/ambient.rs`** — the slow background layer for the **non-book** screens (menu/library/search/settings). `Motif` is `Off | Motes | Contours`, a user setting persisted in `tui.toml` and cycled with `a` on the settings screen; **`Off` is the default**, so the app never starts animating unasked. Never runs on the book view: the object owns that pane, which also keeps the kitty hybrid entirely out of scope.
    - **`animating()` is not widened, ever.** It means "the book is turning" and feeds `params.moving`; fold the ambient layer into it and a parked book reports moving forever and never transmits its crisp frame — with nothing on screen looking wrong. The layer has its own `ambient_visible()` (drawn) / `ambient_animating()` (drifting; frozen under a modal, so opening an input box calms the background rather than making it vanish), and `tick()` splits into `tick_book` + `tick_ambient`. Guarded by `ambient_dirties_without_claiming_the_book_is_moving`.
    - Runs at **`AMBIENT_FPS` = 4, not the 20fps tick**: `advance` reports a change only when the quantized frame index moves, so 4 ticks in 5 cost one integer compare. Same trick as `present.rs`'s pose buckets.
    - Draws through **`blit::blit_sparse`**, a second path beside `blit` (never a replacement — same rule as `raster.rs` beside `render`): coverage-forced split, no `O(2^n)` error search, and uncovered cells left untouched so it composites. Every screen's content box must `Clear` first — a `Block` styles the cells it doesn't draw but never blanks them.
    - **Contour lines are one flat ink, and that is a cost control.** ratatui's diff only skips byte-identical cells; a brightness ramp gave each cell a slightly different averaged colour every frame and repainted the whole terminal — 0.419 MB/s at 200x50, against 0.131 for a full glyph book spin. Flat ink plus a lower `FREQ` took it to **0.019**; motes are 0.006. Bounded by `the_ambient_layer_stays_inside_its_byte_budget`, reported by `ambient_wire_rate`. Ink is the accent pulled to a mid-tone: the terminal background is unknown, so **brightness cannot fade a mote to invisible** — motifs disappear by dropping coverage instead.
    - Line width is normalized by the field gradient (`LINE_HALF_WIDTH`, in *subpixels*). Without it the band's on-screen width tracks the local gradient and the whole thing renders as speckle rather than curves. The noise is made isotropic by scaling the vertical frequency by `4 / cell_h` — an octant subpixel is square, a quadrant one is twice as tall.
  - `ui/mod.rs::book_layout` is `{Split(PaneOrientation), Compact}`. **Split** whenever `width≥26 && height≥8`: the object + a section pane share one divider, at an orientation (`BookTop`/`BookRight`/`BookBottom`/`BookLeft`) that starts from the pane's aspect — portrait→`BookTop` (book above, panel below), landscape→`BookRight` (**panel on the left**, the new default) — and rotates clockwise per the user's `t` presses. **Tab shows/hides the section pane** (`LayoutPrefs { panel, rotation, divider_bias }` on `App`); hidden, the object owns the whole pane. Tab is no longer a tab-cycler — ↑↓ do that — and `ensure_panel` brings the pane back for ↑↓/Enter/→, which would otherwise be dead keys. `[`/`]` slide the divider (`split_rects` carves the two rects + the panel's border side). The divider rule is painted **only when a section is open** — against the bare tab menu it is a line through empty space — but its cell is reserved either way, so opening a section doesn't shift the panel. The object's default span is capped (`split_widths`/`stacked_object_height`, `BOOK_MAX_COLS=50`/`BOOK_MAX_ROWS=26` — ~20% up from the first cut) so a big pane grows the panel, not the book; `divider_bias` lets the user slide past that. Above ~98 columns the composition is **width-capped**: `content_block(area, orientation)` caps at `BOOK_MAX_COLS + PANEL_MAX_COLS` (50+48 — chosen so the two caps agree exactly, since `split_widths(98) == (50, 48)`) or `STACK_MAX_COLS=84` for a horizontal divider, and `split_rects` runs against *that* rect, so `t`/`[`/`]` keep their meaning on a smaller stage. Composing the cap **outside** `split_rects` rather than teaching it to stop tiling is what left all its existing tests valid. **`book_rects` is the book view's entry point** and composes both: the block *sizes* the object, then the object is slid so **its own centre is the window's centre**, with the panel against it on its side (capped, so the far surplus stays margin). Centring the block left the object itself parked left of centre, and the object is the centrepiece. The slide stops as soon as it would take the panel under `PANEL_MIN`, so cramped panes degrade *continuously* back to plain tiling rather than reflowing at a threshold. **Horizontal dividers pass straight through** — the stacked layout keeps its half-and-half spacing, which is what it looks best as; the book reaches the window's middle there by dismissing the pane instead. The floating header is centred over the object, and `menu_box` centres the section menu as a **block** in its pane (per-line centring would shuffle the `› ` caret column); section *content* — Info facts, notes/highlights/cards lists — stays left-aligned. Library/search instead **shrink-wrap**: `list_box(area, widest_row, rows)` sizes the box to its contents (`LIST_CHROME=6` around the widest row, `rows+2` tall) and centres it on both axes, clamped by `LIST_MIN_COLS=34`/`LIST_MAX_COLS=100`/`LIST_MIN_ROWS=7` and then by the pane — so a four-book library is a small centred box, and a long one grows to fill the height and scrolls. `print_lists` is the dev aid. **Compact** (smaller than the split gate) is the object alone, title in the border; opening a section swaps its content in where the object was. The section pane is a single-column **menu** (Info/Notes/Highlights/Cards), *not* tabs: ↑↓ move it, Enter/→ opens a section, Esc/← backs out; the book keeps spinning and the header stays put. Manual book rotation was removed (arrows drive the menu); `space` toggles spin, `r` resets pose, `t` rotates panes, tab shows/hides the section pane, `[`/`]` resize them. Text uses `Color::Reset`/`DarkGray` and `REVERSED` selection so it reads on light and dark terminals; only accents are hard-coded RGB.
- **`crates/cli`** (bin `readingbuddy`) — clap derive subcommands (`search`, `add`, `epub`, `list`, `show`, `rm`, `progress [--reread]`, `note`, `notes`, `links`, `reflect`, `review`, `cite`, `rating scale|map|show`, `highlights`, `merge`, `goodreads import|export`, `ko import|pull|link|scan|sync`, `cards`, `config`, `repl`). `progress` and `show` name the *readings* they touch, not just the book — with rereads one book carries several; `reflect`/`review` take `--reading N` in those same 1-based terms and print the reading they opened. Both reuse `prompt::edit_in_editor`, and `--show`/`--no-edit` exist so opening one is never forced through an editor. `note --kind reflection|review` is refused with the command that does it instead — those two anchor to a reading and there is one of each, which `note` knows nothing about. `rating show` prints every point of the scale including the **unmapped** ones, because an unmapped point is what a review on that value will report instead of a number. `links <note>` prints both directions of the graph and marks a **dangling target as text** rather than dropping it — a wikilink to a note nobody has written is a place to go, not an error; it takes an id or a title fragment through `commands::resolve_note`, the note-side twin of `resolve_one`, because a title is what a `[[wikilink]]` names. `goodreads import <file> [--dry-run] [--new]` and `goodreads export [-o file]`: `--dry-run` prints what would change and names the command that does it, the same refusal-with-a-next-move shape as `ko sync`, and an unmatched row prints its candidates and both moves rather than being a dead end. `ko scan [path]` is read-only and finds the mount itself when the path is omitted (`candidate_mounts`), refusing to guess when two readers are plugged in; `ko sync <path>` with **neither `--all` nor `--book`** prints what would happen and names the flag rather than writing forty books unasked, and an unmatched `--book` selector is an error, never a silent no-op. `ko pull` refuses to create a book when the library holds a near-miss candidate (`--new` overrides) — creating first and warning after would reproduce the silent duplicate `match_candidates` exists to prevent; `ko link` records the decision and then imports, so linking is not a step that appears to do nothing. All printing/prompting lives here (`prompt.rs`, `render.rs`).

## Runtime data (all gitignored)

- Data root: `--data-dir` flag or `READINGBUDDY_DATA_DIR` env, default current dir → `database/app.db` (created + migrated on startup), `database/images/`, `vault/`.

## Conventions

- Every ISBN entering the system goes through `normalize_isbn` — no exceptions.
- Provider failures must degrade (warning), never abort a search/lookup.
- New schema changes = new numbered file in `crates/engine/migrations/`; never edit an applied migration.
- Engine tests use `sqlite::memory:` (Storage caps the pool at 1 connection for in-memory URLs — don't "fix" that). The TUI's `app.rs` tests do the same, and `every_screen_draws_at_every_size` renders every screen from 120x40 down to 1x1 — keep it passing, since a layout panic wrecks the user's tmux pane.
- Truecolor in tmux needs `set -ga terminal-overrides ",*:RGB"`; without it the object's colors quantize to 256.

## Engine standards

The engine is held to a stricter bar than the TUI, and CI enforces it. These are
the rules, and the reasons — the reasons are the part that matters.

- **Degradations are typed, not stringly.** A partial failure returns a
  `Diagnostic` (`diagnostic.rs`) carrying the provider/path plus an
  `ErrorClass`, never a pre-formatted `String`. Its `Display` reproduces the old
  CLI text byte-for-byte, so a change there is a change to user-visible output.
  `Diagnostic` deliberately does **not** hold the source `EngineError`: that
  would cost `Clone`/`Eq`, which the TUI's status buffer and the golden harness
  both need. Add to `ErrorClass` instead.
- **`EngineError::Other` is last-resort.** If a caller might branch on it, it
  deserves a variant.
- **No silently-skipping tests.** A test that `return`s when its fixture is
  absent is green without asserting anything — `epub.rs` had two of those for
  months. Every skip prints `SKIPPED:` and honours
  `READINGBUDDY_REQUIRE_FIXTURES=1`, which turns it into a failure. The nightly
  job sets it, so a broken fetch cannot masquerade as a passing build.
- **Properties where an invariant exists**, in inline `mod props`. Prefer them
  over more examples when the rule is general (checksums, round-trips,
  partitions, orderings). Scope them honestly: `dedup`'s `prefer` fields are
  order-independent and its `fill` fields are not, so only the former is
  asserted permutation-invariant. Asserting something false and then weakening
  it later is worse than asserting less.
- **No network in tests, ever.** The fan-out is tested with a mock
  `MetadataProvider`; timeouts use `#[tokio::test(start_paused = true)]`, which
  is why `PROVIDER_TIMEOUT` must not become a config knob just to be testable.
  `wiremock` is only for real status codes (404/429/500/truncated).
- **Tracing: the engine emits, frontends subscribe.** The engine must never
  install a subscriber. Two hard rules: nothing that can carry an API key goes
  into a field without `googlebooks::scrub_key`, and **highlight text, note
  bodies and search queries are the user's private reading — never above
  `trace!`**. Assert on `Diagnostic`s, not log output; the one exception is
  `tests/tracing_redaction.rs`.
- **Fixtures are generated, not hand-written** (`cargo run -p corpus`). The
  generator does not depend on `readingbuddy` — reusing the engine's own
  parsing to build its fixtures would bake any bug straight into the goldens.
  Tier 1 (`gen-synthetic`) is committed and covers *shape*; tier 2
  (`gen-corpus`, gitignored, `make corpus`) covers *scale and realism*. Shape
  coverage must never sit behind a download.
  Tier 2 emits **one subtree per sidecar layout** — `corpus/generated/modern/`
  and `.../legacy/` — and that split is load-bearing, not tidiness
  (`GENERATOR_VERSION = 2`). Both encode the *same* highlight set of the same
  books, so side by side they share `doc_props.title` (both match one library
  book) and share `datetime`/`pos0`/`text` (their annotations share an
  `identity_hash`) while carrying *different* payloads — page `3i` against
  `7i`, notes only in the legacy one. Import then refreshes every row toward
  whichever sidecar it read last, for ever: every pass reports `updated`, never
  `skipped`, and idempotency can never be observed. No device produces that (a
  mid-migration file carries both layouts in **one** file, where `annotations`
  wins), so the corpus must not either. `the_whole_corpus_imports_idempotently`
  imports one tree per pass and asserts `updated == 0` as well as the skip
  count.
- **Corpus determinism**: `ChaCha8Rng` only — not `StdRng`, whose algorithm may
  change between `rand` versions. Fixed date epoch, never `now()`. Epubs pinned
  by sha256; output pinned by `corpus.lock.json`.
- **`epub` is pinned `=2.1.4`.** It shipped a breaking metadata API change in a
  *patch* release, so a caret constraint is not safe. It is also GPL-3.0 (see
  `deny.toml`), which makes a distributed binary GPL-3.0 as a whole — replacing
  it with `zip` + `quick-xml` would settle both points.
- **Fuzzing needs `-s none`** — ASAN cannot survive mlua's longjmp error
  propagation here; measured, with numbers, in `fuzz/README.md`. Any crash found
  gets minimized into `fuzz/seeds/`, where `tests/fuzz_seeds.rs` replays it on
  stable on every PR. That replay is what makes fuzzing pay off.
- **The panic hook is installed before `setup_terminal`.** `set_hook` chains via
  `take_hook`, so the last hook installed runs first; this ordering gives
  TUI hook → `restore_terminal()` → crash log → default. The hook must never
  take a lock the panicking thread might hold, which is why the crash report
  records the log file's *path* rather than a ring buffer of events.
